# DeepSeek Harness 测试 Agent 插件

编写日期：2026-10-03，Asia/Shanghai。当前状态：**设计与实施计划已整理，产品代码尚未开发，所有阶段功能校验均未执行。**

本方案采用一个原生 TypeScript 插件包，为 DeepSeek Harness（DSH）增加测试模式：把描述性任务转成执行与断言步骤，复用已有插件工具、Skills 和 MCP 执行，保存过程与证据，支持多用例、多数据串行运行，生成一份 HTML 汇总报告。

首版直接在 DSH 内实现计划、调度、断言、记录和报告，不引入外部 Python 服务，不修改 DSH 核心。能否零核心补丁实现，以第一阶段的兼容性验证结果为准。

## 首版约定

| 项目 | 方案约定 |
| --- | --- |
| 主要宿主 | DSH Web 交互入口；CLI 兼容不作为首版必过项 |
| 开发方式 | 独立 TS 插件包，使用 Cordis/DSH 公开接口 |
| 入口 | 拟议 `/test <描述>` 命令，JSON 文件为首个结构化用例导入格式 |
| 执行范围 | 一种浏览器工具/MCP、一种 API 工具/MCP；具体实现于 M0 锁定 |
| 调度 | 一个插件实例同时执行一个批次；批次内实例和步骤串行 |
| 结果 | 本地 JSON、JSONL、证据附件、单一 HTML 报告入口 |
| 断言 | 确定性比较优先；语义模型判断单列，不冒充确定性证据 |
| 审批 | 复用 DSH 在线原生工具审批；跨重启继续审批暂不纳入首版 |
| 中断 | 生成不完整报告，不自动重放有副作用的动作 |
| 停止与清理 | 停止业务派发；在途全部结算后执行预授权清理，收尾超限则隔离并禁止新批次 |
| 动态检查 | 可新增影响结果的必需断言；保存实例实际生效版本，不追溯改判已终结实例 |
| 交付 | 插件包、版本锁定/配置说明、示例、校验记录；不包含独立测试平台 |

这些是为首版收敛的实施默认值，不是已经实现的功能；M0 若发现具体工具能力不满足，应记录差异后调整方案，不悄悄扩大范围。

## 成功标准

- 能把任务转换为可校验计划；缺失预期时明确标注，不能自行编造。
- 能运行真实 Web UI + API 步骤，使用可追溯证据计算断言。
- 能把同一用例三条数据展开成三个实例，分别记录且汇总到一份 HTML。
- 能区分失败、工具错误、阻断、取消和未决；拒绝的动作不执行，缺失断言不通过。
- 能从干净的 DSH 配置安装并重复执行，报告统计与结构化结果完全一致。
