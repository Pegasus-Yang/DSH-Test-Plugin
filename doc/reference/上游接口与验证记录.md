## 3. 实施前需收敛的选择

| 事项 | 本方案默认 | 决定阶段 / 证据 |
| --- | --- | --- |
| DSH安装版本及peer依赖 | 以固定提交为参考，锁定实际可装版本 | M0安装与构建记录 |
| 模型与预算 | 一个主模型，所有循环有界 | M0路由验证、M2规划重复结果 |
| 浏览器/API扩展 | 各选一种满足证据合同的现有实现 | M0真实返回、上下文和取消验证 |
| native/PTC | 首期优先简化为native，不能未经验证强定 | M0调用模式矩阵 |
| 原生审批呈现 | 复用活动运行会话的既有界面 | M0批准/拒绝实测 |
| 结果输出位置 | 项目内可配置output-root，每批次独立目录 | M1路径与写入校验 |
| Skill打包方式 | 使用上游同版本支持的位置/装配方式 | M0加载验证、M6干净安装 |

上述是常规实现选择，现阶段不要求用户逐项审批。若某选择迫使修改核心、增加外部服务或改变功能范围，应先记录影响并重新评审方案。
