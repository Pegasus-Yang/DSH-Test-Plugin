# 当前实现

本文描述 0.5.0。测试增强附着在发起命令的当前 Agent 上；原生请求、工具执行、审批、消息显示、工作区会话保存均由 DSH 负责。历史独立 Agent 方案已被替代，见[改造决策](../design/原生对话增强改造.md)。

| 模块 | 职责 |
| --- | --- |
| index.ts | 注册命令、限制输入路径、注册认证报告路由 |
| language.ts | 读取宿主语言偏好，约束原生对话的用户可见说明语言 |
| text-plan.ts | 自然语言短句计划、文字检查点和纯文字审核呈现 |
| native-test.ts | 当前 Agent 的测试作用域、指导、工具、原生事件观察、停止与清理 |
| config.ts | 测试阶段的时间和修订预算 |
| contracts.ts / revisions.ts | 冻结计划、身份校验、追加检查点、实例与结果聚合 |
| adapters.ts / assertions.ts | 可信工具响应采集、固定比较器、操作数证据绑定 |
| recorder.ts | 插件自身的脱敏账本、快照、证据和只读重建 |
| report.ts / report-access.ts | 静态 HTML 报告与受宿主认证保护的访问路径 |

## 正常执行

1. 命令调用当前 `Agent.followup()` 提交真实用户输入。命令只确认接收，输入框随即回到原生运行状态；本轮执行仍占用同一个对话。不会建立后台任务或额外 Agent。
2. 在 `agent.ctx` 注册 `systemPrompt.section()` 与测试工具。模型仅根据用户输入分析、规划、追问；工具守卫禁止规划阶段浏览器、API和命令执行；用户补充信息仍进入同一对话。自然语言提交包含name、简短rationale、steps[].description及可选checks[]，插件生成身份和文字规则来源；冻结的是业务短句，而不是预先编译的动作。
3. 模型按正常循环调用 Playwright 工具。`test_capture` 通过同一 Agent 的原生工具管线调用可信采集器，保留父调用、取消信号和原有审批策略。程序计算断言，不接受模型填写实际值。
4. `session/event` 只读观察调用身份；`tools/result` 记录最终工具结果。所有插件账本写入项目输出目录，插件不追加自定义 DSH 事件、不改写宿主日志或浏览器本地状态。
5. `test_finish` 返回权威状态、逐步结果、断言、路径和报告链接，模型在原生最终回复中总结。轮次结束后移除测试提示、工具和监听器，后续普通聊天沿用原会话。

不存在客户端进度模块、全局浮层或定时轮询快照。中间推理和调用按宿主默认方式显示，已完成步骤是否折叠由 DSH 控制；可展开工具记录或查看轨迹。

## 停止与清理

原生停止按钮或 `/test-stop` 禁止后续业务动作。等待当前 Agent 的在途操作结算后，用同一 Agent 的 `followup()` 发起明确标记的清理轮次；只准入冻结的当前清理步骤及必要采集/结算工具。不会创建清理会话，也不会恢复业务步骤。用户停止记录 CANCELLED；规划或步骤超时记录 ERROR 并注明超时原因。

未能在取消宽限期内结算、清理失败或重启发现未结算运行时持久隔离共享资源，拒绝下一批测试。迟到结果仅记录审计，不改写封存结果。解除必须提供实际停止与环境重置证据。

## 边界

- 模型、MCP、审批、轮次配置复用当前 Agent；只支持 native 工具模式。推荐宿主 `maxParallelToolCalls: 1`，测试增强另行拒绝并发步骤提交。
- 同一插件同时只允许一个活动测试，浏览器实例必须专用于测试。每个数据实例顺序执行，初始化/清理在同一会话完成，浏览器上下文依实例释放。
- API 采集只支持 GET JSON；网页地址用 DOM 的 url 模式。自然语言计划只固定业务短句和文字检查点；能力、目标在当前步骤执行时通过 test_define_step 确定，输出类型由采集方式登记，选择器/接口字段通过 test_capture 绑定，比较器通过 test_bind_check 绑定，可根据实际页面修正并记录原因。已采集观察不可覆盖，只能补采缺少输出。JSON 默认沿用固定 capture，也可显式声明 capture_mode: runtime。
- 不再提供旧 `testRunner` 自定义调度和 hook 接口。其他插件使用宿主公开事件与工具扩展点，不依赖独立执行器。
- 模型最终文字仍属于模型输出；可核验结果是 `test_finish`、报告及账本。失败、阻塞或缺少观察不能口头改判通过。
- 报告链接默认对应本机 DSH HTTP 端口；远程代理部署需按实际浏览器服务地址访问相同 `/test-reports/` 路径。离线 HTML 始终可用。

运行时采集方式保存在步骤的 `capture_attempts` 和 `capture_configured` 事件中，原始 plan.json 不被改写。规划阶段只允许计划提交、状态查询、待办与用户追问；规划停止不派发浏览器清理。

## 原生计划审核

`/test-plan` 使用官方 `commands.find/execute` 解析当前 Agent 的 `/plan` 命令，在原会话设置 plan 模式。Web 预设把 plan 服务放在隔离组中，不能从全局或 Agent 根 Context 直接读取该服务。`test_submit_plan` 校验并保存可替换的 `plan-draft.json`，此时不展开实例、不启动动作。插件生成只包含业务短句和文字检查点的审核 Markdown，工具守卫要求 `exit_plan_mode` 审核参数与当前草案完全一致，确保用户批准的是当前文字草案。观察原生工具成功结果 `{ approved: true }` 后才冻结同一草案；拒绝、要求修改、停止或单纯 `/plan off` 均不会放行执行。审核工具及用户交互由宿主提供，插件不伪造宿主审批事件。

草案提交后停掉规划计时器，人工审核时间不限；执行超时从批准后的具体动作开始。每次草案及批准调用ID进入插件账本。未批准取消恢复进入前的模式；批准退出由宿主处理。宿主未提供原生 `/plan` 命令时仅 `/test-plan` 返回明确错误，原有入口不受影响。

纯 API 计划复用相同状态机和报告：`test_capture` 经原生管线调用 `test_api_get`，以 `http-json-v1` 保存原始响应并提取观察；同一个对象观察可绑定状态码、响应体等多条嵌套字段断言，无浏览器初始化、关闭或截图阶段。

## 文字步骤的运行时定义

文字步骤以 kind=intent 和 checks 保存，JSON文件入口仍仅接受完整action/assertion契约。plan.json保持原文不变；每个检查点在展开实例时生成固定必需ID，缺少绑定不能视为通过。进入当前步骤后才允许 test_define_step，采集方式决定本步输出类型，模型无需重复声明Schema；不能修改未来步骤或已有观察，但可以补采新输出。首次实际定义浏览器步骤才初始化浏览器并登记同会话清理，纯接口计划不触发浏览器。

test_bind_check以check_index选择当前文字规则，插件固定rule_ref及必需身份；模型负责在当前上下文中把文字预期转换为比较器和引用，不得从观察反推预期。结构、类型、引用由既有契约校验，结果仍由确定性比较器计算。自然语言含义的一致性依赖模型理解，记录原文、文字检查点、实际定义和证据供审计，不能把结构校验称为自然语言语义的程序证明。

运行定义进入实例effective_steps及step_defined/check_bound事件，原始文字计划不会被替换。动态追加检查仍保留尚未执行的文字检查必需集合，避免追加后丢失原有检查义务。

明确的简单数字条件（如“不为0”“状态码为200”）在绑定断言时检查数值和比较器一致性，不能用数字字符串或不同预期替代。此检查不在规划阶段生成操作参数，也不是对任意自然语言的完整语义验证。

## 规划说明与语言

`plan.planning` 保存插件提供的原始任务和面向用户的一两句拆分说明，不作为新增断言的授权来源。审核卡片和 `/test` 的提交结果都包含原始任务、拆分思路、步骤清单；普通入口要求模型在正常对话中先通报，再执行。用户追加说明仍记录到规则来源，原始任务不会被模型摘要替换。

每次组装测试提示时通过宿主公开 `settings.describe({redactSecrets:true})` 读取 locale.preference；不可用或未设置时沿用用户消息语言。DSH浏览器自动推断的locale未暴露给Host模型请求，本实现不声称能读取所有浏览器临时语言。语言指导覆盖进度、简短分析、工具reason、计划和最终回复；原始资料保持原文。
