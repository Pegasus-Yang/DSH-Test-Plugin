# 当前实现

本文描述 0.2.0。测试增强附着在发起命令的当前 Agent 上；原生请求、工具执行、审批、消息显示、工作区会话保存均由 DSH 负责。历史独立 Agent 方案已被替代，见[改造决策](../design/原生对话增强改造.md)。

| 模块 | 职责 |
| --- | --- |
| index.ts | 注册命令、限制输入路径、注册认证报告路由 |
| native-test.ts | 当前 Agent 的测试作用域、指导、工具、原生事件观察、停止与清理 |
| config.ts | 测试阶段的时间和修订预算 |
| contracts.ts / revisions.ts | 冻结计划、身份校验、追加检查点、实例与结果聚合 |
| adapters.ts / assertions.ts | 可信工具响应采集、固定比较器、操作数证据绑定 |
| recorder.ts | 插件自身的脱敏账本、快照、证据和只读重建 |
| report.ts / report-access.ts | 静态 HTML 报告与受宿主认证保护的访问路径 |

## 正常执行

1. 命令调用当前 `Agent.followup()` 提交真实用户输入。命令只确认接收，输入框随即回到原生运行状态；本轮执行仍占用同一个对话。不会建立后台任务或额外 Agent。
2. 在 `agent.ctx` 注册 `systemPrompt.section()` 与测试工具。模型正常阅读用户输入、只读探索、追问；用户补充信息仍进入同一对话。计划通过校验后冻结。
3. 模型按正常循环调用 Playwright 工具。`test_capture` 通过同一 Agent 的原生工具管线调用可信采集器，保留父调用、取消信号和原有审批策略。程序计算断言，不接受模型填写实际值。
4. `session/event` 只读观察调用身份；`tools/result` 记录最终工具结果。所有插件账本写入项目输出目录，插件不追加自定义 DSH 事件、不改写宿主日志或浏览器本地状态。
5. `test_finish` 返回权威状态、逐步结果、断言、路径和报告链接，模型在原生最终回复中总结。轮次结束后移除测试提示、工具和监听器，后续普通聊天沿用原会话。

不存在客户端进度模块、全局浮层或定时轮询快照。中间推理和调用按宿主默认方式显示，已完成步骤是否折叠由 DSH 控制；可展开工具记录或查看轨迹。

## 停止与清理

原生停止按钮或 `/test-stop` 禁止后续业务动作。等待当前 Agent 的在途操作结算后，用同一 Agent 的 `followup()` 发起明确标记的清理轮次；只准入冻结的当前清理步骤及必要采集/结算工具。不会创建清理会话，也不会恢复业务步骤。

未能在取消宽限期内结算、清理失败或重启发现未结算运行时持久隔离共享资源，拒绝下一批测试。迟到结果仅记录审计，不改写封存结果。解除必须提供实际停止与环境重置证据。

## 边界

- 模型、MCP、审批、轮次配置复用当前 Agent；只支持 native 工具模式。推荐宿主 `maxParallelToolCalls: 1`，测试增强另行拒绝并发步骤提交。
- 同一插件同时只允许一个活动测试，浏览器实例必须专用于测试。每个数据实例顺序执行，初始化/清理在同一会话完成，浏览器上下文依实例释放。
- API 采集只支持 GET JSON；网页地址用 DOM 的 url 模式。选择器在计划冻结后不能悄悄改写，失配应报错并重新规划新运行。
- 不再提供旧 `testRunner` 自定义调度和 hook 接口。其他插件使用宿主公开事件与工具扩展点，不依赖独立执行器。
- 模型最终文字仍属于模型输出；可核验结果是 `test_finish`、报告及账本。失败、阻塞或缺少观察不能口头改判通过。
- 报告链接默认对应本机 DSH HTTP 端口；远程代理部署需按实际浏览器服务地址访问相同 `/test-reports/` 路径。离线 HTML 始终可用。
