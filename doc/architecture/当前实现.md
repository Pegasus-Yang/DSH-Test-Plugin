# 当前实现

本文描述0.1.0代码；历史设计和完整验收目标保存在doc/design，不把尚未验证的目标当成现有保证。

| 模块 | 职责 |
| --- | --- |
| index.ts | 原生命令装配、工作区输入限制、testRunner服务 |
| contracts.ts | 计划Schema、跨引用校验、实例展开、终态聚合 |
| planner.ts | 独立规划Agent；只提供提交计划和询问缺口工具 |
| revisions.ts | 校验追加断言、持久化修订与逐实例应用 |
| runner.ts | 串行实例/步骤、四类hook、停止、清理与持久隔离 |
| host.ts | Harness Agent及工具管线适配、前置绑定、原生审批、有限预算 |
| adapters.ts | Playwright固定DOM采集、GET JSON与浏览器关闭证据 |
| assertions.ts | 固定比较器、观察身份检查和不可回溯操作数快照 |
| recorder.ts | JSONL串行fsync、原子结果快照、脱敏、摘要及只读重建 |
| report-access.ts / report-notice.ts | 最近报告恢复、受宿主认证保护的静态文件路由、网页完成提示 |
| report.ts | 自包含HTML、三维筛选、附件和缺失证据提示 |

每个业务实例有独立Harness会话，清理使用另一个会话与新取消信号。浏览器工具配置必须专用于测试；目前一个插件实例只运行一个批次。实例开始时关闭旧浏览器上下文，首次导航创建隔离上下文；结束后通过MCP关闭并记录证据。未显式配置关闭清理时runner补充内部释放步骤。

模型native调用在session/event的tool/call阶段登记callId；可信嵌套采集在进入ctx.tools.execute之前登记。tools/result保存规范结果，session/tool结果补齐提前取消等路径。管线和结束时均检查当前步骤是否仍准入。所有观察保存case/phase/step/attempt/call/context身份；断言取指定槽，不选“最近值”。

停止后冻结业务入口、传播取消并独立等待cancelGraceMs。无法证明结算时封存ERROR及不完整结果，写持久隔离标记，拒绝后续批次和清理；迟到结果只追加审计。重建不重放工具，也不尝试自动恢复审批。

当前接入锁定native、同批最大并发1；不宣称PTC受支持。API为经相同原生工具管线注册的只读HTTP GET JSON adapter，不提供通用写接口。采集选择器冻结后不由模型修改；网站变化可能导致明确ERROR，需要审查后新建计划重新运行。

模型路由沿用用户本机Harness配置，验收实际使用MiniMax路由；“DeepSeek Harness宿主”不等于一定使用DeepSeek模型。报告不保存API凭据。截图可能包含页面信息，不进行视觉内容自动脱敏；只应归档当前授权测试页面。
