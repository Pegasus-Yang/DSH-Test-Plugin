## 命令

第一次启用浏览器浮窗，请按[浏览器实时预览一步一步配置](浏览器实时预览一步一步配置.md)操作：安装 Browscreen 命令，在“设置 → 测试插件”检测安装，保存启用、命令路径、端口和 Playwright 选择，之后继续使用下面的命令即可。设置修改在下一次测试生效，API 或无 CDP 任务不会出现空浮窗。

| 命令 | 用途 |
| --- | --- |
| `/test <描述>` | 在当前对话分析并生成计划，校验通过后直接执行，无需确认 |
| `/test-plan <描述>` / `/test-plan --file <路径>` | 审核任务或 TXT/Markdown 用例的文字步骤后执行 |
| `/test-run <文件路径>` | 读取 TXT 或 Markdown 用例，规划通报后执行 |
| `/test-data <CSV路径> <模板或--file 路径>` | 展开参数，审核所有实例的原文、参数和步骤后执行 |

其他操作直接在界面完成：查看状态用输入框上方的进度区；停止用 DSH 原生“停止生成”；报告重建用运行结束后的“重建报告”或“设置 → 测试插件 → 测试报告”；异常处置和证据提交用“设置 → 测试插件 → 测试环境”。只有上表四个斜杠命令。

自然语言用例请直接输入：

```text
/test 访问ceshiren.com，搜索 agent 关键字，并打开第一条搜索结果帖子，断言帖子的点赞数不为0
```

`/test-run` 接受已保存的 TXT 或 Markdown 文件路径，不能在其后直接填写自然语言任务。在网页命令菜单选择命令后继续输入对应参数再提交。命令处理结果应显示为DSH命令记录；普通聊天中的模型总结不能代替插件运行记录和报告。

## 文件用例与 CSV 参数化

```text
/test-run examples/httpbin-cases.txt
/test-run examples/httpbin-cases.md
/test-plan --file examples/httpbin-cases.md
/test-data examples/httpbin-parameters.csv 请求https://httpbin.org/get?keyword=${keyword}，验证状态码为200，返回keyword为${keyword}
/test-data examples/httpbin-parameters.csv --file examples/httpbin-parameterized.md
```

以上示例逐条运行。文件均为 UTF-8，可用引号包裹含空格的路径。文件入口按发起命令的当前对话工作区解析；没有工作目录信息的历史会话才回退到插件配置的 `workspace`。

例如，先把 `/你的目录/DSH-Testing` 添加到 DSH，在这个工作区内新建或打开对话，并把 `ui.md` 放在目录根部。`/test-run ui.md` 与 `/test-run /你的目录/DSH-Testing/ui.md` 均读取这一个文件。仅添加其他工作区不会改变原对话的目录；应进入目标工作区的对话。绝对路径也必须位于当前对话工作区内；上级目录和指向外部的符号链接仍会被拒绝。文件找不到时，错误会给出实际查找路径和工作区，先核对这两个位置。

`/test-plan --file` 和 `/test-data` 的 CSV、用例文件遵循同一规则。TXT 每个非空行一条用例；Markdown（`.md` 或 `.markdown`）最外层列表项各一条，有序、无序均可，嵌套列表、表格和代码块留在所属用例内。列表外说明作为共享背景展示，不另算用例；代码块中的列表不算用例。完整示例见上述文件。

CSV 首行为参数名，例如：

```csv
keyword,client
agent,dsh
testing,web
```

每个用例依次使用全部数据行，2 条用例和 2 行 CSV 展开为 4 个实例。`${keyword}` 等占位符按列名替换，支持重复引用，不执行表达式、不递归替换参数值里的占位符。CSV 支持带引号的逗号、换行和转义双引号；参数值保留前导零、空字符串和空格。空白行忽略，合法空字段记录保留。缺失参数列、重复/空表头、列数错误、无数据会在启动前提示；额外列保留供审核。

`/test-data` 始终进入原生 plan 模式。审核页列出原始命令、来源文件、原始用例数、CSV 数据行数、执行实例总数，以及每个实例的来源用例、数据行、所有参数、完整展开任务、拆分思路和步骤。模型不能删除或合并导入实例，也不能替你修改 CSV 值。可要求修改文字步骤并重新审核；更改用例文件或 CSV 后，应取消当前草案并重新提交，因为本次运行使用读取快照。

批准前不访问目标。批准后仍在同一对话逐实例串行执行，工具参数和定位留到当前步骤决定。报告按实例统计，支持按来源用例、数据行筛选；“用例来源与参数”展示对应原文、参数和展开任务。报告下载的计划保留完整输入快照；运行目录额外包含 `input.json`。原始输入与运行分析分别保留。

## 在当前对话查看执行过程

新建会话后可直接输入 `/test <任务与预期>`，无需先发送普通聊天。命令把真实任务提交给当前 Agent，会话由 DSH 正常保存和命名。执行过程就是普通对话：计划说明、浏览器调用、工具结果、审批、追问和最终总结均保留在本会话中。已完成工具可能按宿主默认行为折叠，可点击展开或查看“轨迹”。

`/test` 只把用户描述拆解为文字步骤和检查点，不在规划时指定工具、选择器、能力类型、输出Schema、字段路径或比较器。`/test-run <文件路径>` 读取文字文件后在当前对话规划执行。测试模式只作用于发起会话，结束后撤销，普通后续聊天不受测试工具约束。其他新会话不会出现历史报告浮层。

点击原生“停止生成”按钮停止业务动作；在途结算后，本会话会出现原生收尾轮次，执行冻结的清理，最后给出取消或错误结果及报告。不能证明在途结算时不运行清理，而是封存结果并隔离共享环境。

### 浏览器操作录像

0.11.2 支持 Browscreen 0.3.x 录像。先安装 `browscreen[video]==0.3.0`，在“设置 → 测试插件 → 浏览器预览与录像”勾选“录制浏览器操作视频”并保存。开关独立于实时预览，默认关闭；四个测试命令共用此设置，关闭浮窗或网页后仍录制，宿主服务需保持运行。

测试结束后，在报告选择对应浏览器实例，点击“操作录像”，播放、拖动时间轴或下载 MP4。每个实例保留自己的片段；接口实例没有视频入口、截图对话框或空媒体占位。依赖或收尾失败时给出提示，不修改业务断言。详细安装步骤、部分录像说明和完整目录离线保存见[浏览器录像与报告](浏览器录像与报告.md)。

## 先审核再执行

```text
/test-plan GET https://httpbin.org/get?keyword=agent&client=dsh，断言HTTP状态码为200，响应body.args.keyword为agent，body.args.client为dsh
```

需要宿主已启用 `dsh-plan-mode` 和原生用户审核通道。插件通过官方 `commands.execute(agent, "/plan", ...)` 进入 plan 模式，仍在当前对话分析描述；规划阶段禁止浏览器、API和命令执行。

模型先用 `test_submit_plan` 保存草案，再通过原生 `exit_plan_mode` 展示“计划待审”卡片。点击“查看全文”审核业务短句及文字检查点；选择“要求修改”后在对话中输入修改意见，模型更新草案并重新展示审核。只有批准当前草案才冻结为 `plan.json` 并开始执行；直接关闭 plan 模式不能跳过审核。等待审核不计入执行超时，原生“停止生成”按钮可以取消，取消前未执行则不派发清理工具。

## 文字规划与逐步执行

例如“访问ceshiren.com，搜索agent，打开第一条结果，断言点赞数不为0”可拆为：

1. 访问测试人社区。
2. 搜索 agent。
3. 打开第一条搜索结果。
4. 查看帖子点赞数，检查点赞数不为 0。

规划通报和审核卡片按“原始任务、拆分思路、步骤清单”展示。原始任务由插件保留，拆分思路用一两句说明动作顺序和检查目的，方便对照；不展开详细推理。网站结构、点击位置、请求参数、输出字段和比较器在执行到当前步骤时再分析，不要求用户提前知道未知页面细节。

模型用 `test_define_step` 设置当前步骤的能力和目标范围，不需要填写输出Schema；观察和操作页面后直接通过 `test_capture` 绑定采集位置，输出类型由采集方式自动登记。纯API可直接收集完整响应对象。当前步骤的每个文字检查点用 `test_bind_check` 关联可信观察和比较器，预期仍来自原文和文字清单。检查可以复用前一步观察，不重复发送请求。每项检查都要有程序计算结果，不能只口头判定通过。

原始文字计划保留在 plan.json，具体执行定义保存在实例的 effective_steps，账本记录 step_defined、capture_configured、check_bound。报告可展开“原始文字步骤与检查点”对照实际执行记录。`/test-plan` 审核文字后执行，`/test` 直接执行，原始输入与本次运行分析分别保留。

## 纯接口测试示例

```text
/test-run examples/httpbin-cases.md
```

文件中的接口用例向 [httpbin](https://httpbin.org/) 发送 GET，检查 HTTP 状态码和查询参数回显。每次响应可供多个检查复用，无需为每个检查重复请求。不调用 Playwright，不初始化浏览器，也不产生浏览器截图；附件保留接口响应。当前接口采集支持 GET JSON，不支持 POST 或自定义请求体。

## 查看测试报告

最终回复会提供 **查看测试报告** 链接与完整保存位置，链接指向本机 DSH 的 HTTP 端口，可直接在浏览器查看。报告是静态 HTML：直接打开 `artifacts/runs/<运行ID>/report.html` 也能查看，不需要专门报告服务。复制整个运行目录可保留相对路径证据附件。

报告需要重新生成时：

1. 当前运行结束后，在进度区或完整详情中点击“重建报告”，完成后点击“查看重建报告”。
2. 想找旧运行时，进入“设置 → 测试插件 → 测试报告”。
3. 填写实际运行 ID，例如报告中的 `run-…`。留空时只使用当前所选对话的报告，绝不回退到另一个对话的最近报告。
4. 点击“重建报告”，等待“查看重建报告”链接出现后打开。运行 ID 可从原报告或输出目录名称中找到。

仍在执行的测试不能重建。中断记录可按已保存事实重建，会明确标记不完整，不会补执行步骤。重建不调用模型或业务工具，原记录不被覆盖，生成 `report-rebuilt.html`、`results-rebuilt.json`、`actual-steps-rebuilt.json` 和 `manual-cases-rebuilt.md`。

网页访问复用 DSH 登录保护，服务关闭后 HTTP 链接不可用，但本地 HTML 仍可打开。无 Web 服务时保留本地路径。若通过远程代理访问 DSH，请将报告链接的本机地址替换为实际 DSH 地址，报告路径保持不变。

## 动态检查、扩展与结果

模型可通过test_propose_checkpoint提交已有来源支持的追加断言，必须显式列出适用实例、required、插入边界和post_hoc。只允许向未终结实例的未来边界追加，不可改原步骤；新增来源、业务写动作或扩权需要重新提交经确认的计划。实例记录自身有效修订和必需集合，已结束实例不追溯改判。

其他插件沿用 DSH 官方事件、工具及审批扩展点；0.3.0 不再暴露旧独立执行器的 `testRunner.hook`。

报告按准备/业务/清理展示清晰步骤，包含实际/预期、来源操作数ID、工具调用、附件摘要。可按case、data和状态筛选。必要断言FAIL与必要清理ERROR会同时保留，主状态取ERROR。未开始的取消实例仍计入总数。

## 实际步骤与手工用例

新运行自动保存每个浏览器业务操作的简短说明和真实调用；每个用例/数据实例单独从 1 编号，重试与失败保留。报告有记录时默认显示“实际步骤”，可下载当前实例或完整批次的运行记录与 Markdown 手工用例。准备和业务收尾另列，插件自动复位关闭不占编号；纯接口记录请求与检查，不出现浏览器媒体。运行报告中未定义的中间预期标明待补充。手工 Markdown 只保留名称、用户原文、前置、实际步骤和收尾；步骤中合并真实数据与地址，没有预期时留空，不含本轮状态、证据或实际结果。详见[实际步骤与手工用例](实际步骤与手工用例.md)。

## 查看报告

报告默认打开“测试用例”：左侧按名称、用例、数据集和状态筛选，右侧有新增记录时默认打开实际步骤，也可切换原步骤、断言和附件。步骤可展开工具调用和采集调整记录；断言中的“查看证据”跳转到本次实际响应或截图。概览按真实用例状态统计，并区分断言通过数与已执行数；取消、阻塞及未执行不会计为通过。运行信息包含起止时间、配置与原始数据入口。总耗时包含规划，步骤耗时为步骤时间之和，两者用途不同。

离线保存请复制完整 `run-…` 目录：单独 HTML 可以查看结论、步骤、断言及内嵌截图和运行记录 JSON 下载；手工 Markdown 下载也需要独立文件，账本下载与 MP4 回放需要同目录内的原始文件。重建仍保留原件，生成独立 -rebuilt 文件。

明确的简单数字条件（如“不为0”“状态码为200”）在绑定断言时检查数值和比较器一致性，不能用数字字符串或不同预期替代。此检查不在规划阶段生成操作参数，也不是对任意自然语言的完整语义验证。

## 对话语言

模型面向用户的简短分析摘要、规划说明、步骤进度、工具调用说明、追问和最终结论，优先跟随 DSH 已保存的 `locale.preference`。宿主没有显式偏好（例如浏览器自动选择语言）时，沿用用户当前输入语言。当前中文任务默认简体中文，URL、代码、字段名和原始响应保留原样。插件通过宿主公开设置接口读取偏好，不修改 DSH 设置，也不改写历史消息。

常见断言预期在运行时直接填写原文，例如 agent 或 200，不需要 JSON 引号包装；类型由明确数字条件和可信观察确定。复杂对象或数组才使用 JSON。检查按文字清单的顺序结算，不能用动态追加检查覆盖尚未绑定的既定检查。

## 规划结束后没有执行

只有文字分析还不等于插件保存了计划。普通测试会提醒模型提交一次，提醒不重置规划预算；再次结束而未提交时，记录未执行错误并结束会话，不长期停在 0/0。需要补充信息时按原生问题提示回答；计划审核等待用户确认，不自动批准。
