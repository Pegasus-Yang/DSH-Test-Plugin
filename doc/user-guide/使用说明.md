# 使用说明

## 命令

| 命令 | 用途 |
| --- | --- |
| `/test <描述>` | 由独立规划会话生成计划并执行；没有明确预期则返回问题 |
| `/test-run <JSON路径>` | 导入并执行工作区内的完整测试集合，不隐式丢弃错误数据行 |
| `/test-status` | 当前批次、实例、业务/清理会话、统计和隔离状态 |
| `/test-stop` | 停止新业务动作；在途结算后执行预授权清理 |
| `/test-report [运行ID]` | ID可省略，默认最近报告；只读重建为 `report-rebuilt.html` 和 `results-rebuilt.json`，不调用模型或工具 |
| `/test-release <处置JSON路径>` | 核实并记录处置后解除隔离，详见运维文档 |

自然语言用例请直接输入：

```text
/test 访问ceshiren.com，搜索 agent 关键字，并打开第一条搜索结果帖子，断言帖子的点赞数不为0
```

`/test-run` 只接受已保存的JSON测试集合路径，不能在其后直接填写自然语言任务。在网页命令菜单选择 `/test`、`/test-run` 或 `/test-release` 后，继续输入对应参数再提交；`/test-report` 的运行ID可以留空。命令处理结果应显示为DSH命令记录；普通聊天中的模型总结不能代替插件运行记录和报告。

## 在当前对话查看执行过程

`/test` 和 `/test-run` 会占用当前命令提交过程，直到测试与清理全部结束才返回，不再仅返回“已启动”后让用户自行查询。对话中的“测试执行进度”持续显示规划、当前步骤、准备/业务/清理阶段、工具执行状态、采集值，以及断言的实际值、预期值与判定。结果来自运行账本，不采用模型自行总结的结论。

点击进度中的“停止测试”可中止新业务动作，在途操作结算后仍执行预先授权的清理，最终结果继续显示在同一对话。旧运行的停止按钮不会停止另一个新批次。进度快照保存在输出目录的 `conversation/` 中，并按命令关联到发起对话；切换回来、刷新或重启宿主后可回看已结束测试。

底层规划、业务和清理仍使用独立Agent会话保证隔离，但不需要跳转才能查看步骤。需要详细工具上下文或出现“等待审批”时，可点击“查看工具与审批”“查看规划会话”或“查看清理会话”进入对应会话。拒绝必要动作后实例 BLOCKED；拒绝必要清理后为 ERROR。审批等待也受步骤预算约束。

## 查看测试报告

测试结束后，发起对话的进度记录直接显示最终结果、完整保存位置和 **查看测试报告** 链接，点击在新标签页打开。右下角的完成提示仍作为辅助入口，可收起再展开；不需要查找ID或复制文件路径。

输入 `/test-report`（不带参数）也能显示最近报告入口；重启插件后仍从输出目录找回最近完成的报告。输入 `/test-report <运行ID>` 可查看指定历史运行。运行中不会把尚未完成的报告当成最终报告提供。

报告是**自包含的静态HTML**，可以直接打开 `artifacts/runs/<运行ID>/report.html`，无需专门的报告服务。完整复制运行目录后，筛选、步骤和相对路径附件仍可离线查看。

网页按钮使用当前DSH服务的 `test-reports/<运行ID>/report.html` 路径，复用当前登录态，支持截图和原始响应附件；需要DSH服务处于运行状态。未登录不能通过链接读取报告。关闭DSH后仍可直接打开本地HTML，报告文件不会删除。无Web服务的宿主仍可使用本地文件路径。

提示展示同一宿主测试插件的最近运行；无需留在独立业务/清理会话才能看到。升级插件后需重启DSH，并刷新已打开的网页，以加载新入口。

## JSON计划

完整示例见 `examples/ceshiren-agent.json`。一个 suite 含多个 case，每个 case 的 datasets 各自展开；例如两例分别2行和3行得到5个实例。空 datasets 自动产生 default 行。

准备、业务和清理复用 Step 结构；ID在同一用例跨阶段唯一，不得使用内部保留前缀 `__`。依赖只能指向前序；必需步骤不能引用可选输出。每例至少有一个必需业务断言。

动作必须声明目标URL、目标描述、输入、输出JSON Schema、必要输出和采集方式。输入支持 `{"input_ref":"data.inputs.key"}`、`{"resource_ref":"browser_context"}`、`{"literal":值}` 或直接JSON值。当前资源登记只支持独占的浏览器上下文。

`capture` 按输出名称定义可信采集：

| kind | 字段 | 行为 |
| --- | --- | --- |
| dom | selector、mode、可选index/attribute/field | 固定只读DOM函数；除显式index外必须唯一匹配 |
| http | url、field | 原生工具管线内执行HTTP GET并读取JSON，如 `body.amount` |
| browser_close | 无 | 通过Playwright MCP关闭上下文，以成功响应生成released=true |

DOM mode支持text、number、count、visible、url、attribute、value；url默认完整网址，field=pathname只取路径；index从0开始，用于明确的第几条结果。number只接受明确十进制文本，不把缺失/空白转换成0。缺少必要输出是ERROR；声明为非必要的输出缺失导致对应断言INCONCLUSIVE。观察槽只绑定一次，重复采集不覆盖旧值。

断言支持eq、neq、contains、range、exists、text、visible。预期在literal、data.expected引用、另一观察引用中恰选一种，规则必须有source_refs来源。neq保留类型要求，字符串"1"不会冒充数字1。range必须给单位、容差和两个数值边界。

## 动态检查、扩展与结果

模型可通过test_propose_checkpoint提交已有来源支持的追加断言，必须显式列出适用实例、required、插入边界和post_hoc。只允许向未终结实例的未来边界追加，不可改原步骤；新增来源、业务写动作或扩权需要重新提交经确认的计划。实例记录自身有效修订和必需集合，已结束实例不追溯改判。

其他原生插件可声明inject: ['testRunner']，用 `ctx.testRunner.hook(name, handler)` 注册 before_step、after_observation、after_assertion、report_ready；返回清理函数随作用域释放。传入的是深度冻结副本；后置hook只能观察，不可改历史。before_step返回false拒绝步骤，抛错为步骤ERROR；后置错误记警示。所有hook有独立预算。

报告按准备/业务/清理展示清晰步骤，包含实际/预期、来源操作数ID、工具调用、附件摘要。可按case、data和状态筛选。必要断言FAIL与必要清理ERROR会同时保留，主状态取ERROR。未开始的取消实例仍计入总数。
