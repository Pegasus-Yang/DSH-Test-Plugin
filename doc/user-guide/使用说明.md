# 使用说明

简体中文 | [English](使用说明.en.md) · [项目首页](../../README.md)

## 命令

| 命令 | 用途 |
| --- | --- |
| `/test <描述>` | 在当前对话分析并生成计划，校验通过后直接执行，无需确认 |
| `/test-plan <描述>` / `/test-plan --file <路径>` | 审核任务或 TXT/Markdown 用例的文字步骤后执行 |
| `/test-run <文件路径>` | TXT、Markdown 用例先规划通报后执行；JSON 使用完整执行定义 |
| `/test-data <CSV路径> <模板或--file 路径>` | 展开参数，审核所有实例的原文、参数和步骤后执行 |
| `/test-status` | 当前批次、实例、业务/清理会话、统计和隔离状态 |
| `/test-stop` | 停止新业务动作；在途结算后执行预授权清理 |
| `/test-report [运行ID]` | ID可省略，仅查看当前会话报告；只读重建为 `report-rebuilt.html` 和 `results-rebuilt.json`，不调用模型或工具 |
| `/test-release <处置JSON路径>` | 核实并记录处置后解除隔离，详见运维文档 |

自然语言用例请直接输入：

```text
/test 访问ceshiren.com，搜索 agent 关键字，并打开第一条搜索结果帖子，断言帖子的点赞数不为0
```

`/test-run` 接受已保存的 TXT、Markdown 或 JSON 文件路径，不能在其后直接填写自然语言任务。在网页命令菜单选择命令后继续输入对应参数再提交；`/test-report` 的运行ID可以留空。命令处理结果应显示为DSH命令记录；普通聊天中的模型总结不能代替插件运行记录和报告。

## 文件用例与 CSV 参数化

```text
/test-run examples/httpbin-cases.txt
/test-run examples/httpbin-cases.md
/test-plan --file examples/httpbin-cases.md
/test-data examples/httpbin-parameters.csv 请求https://httpbin.org/get?keyword=${keyword}，验证状态码为200，返回keyword为${keyword}
/test-data examples/httpbin-parameters.csv --file examples/httpbin-parameterized.md
```

以上示例逐条运行。文件均为 UTF-8，路径在配置的 workspace 内，可用引号包裹含空格的路径。TXT 每个非空行一条用例；Markdown（`.md` 或 `.markdown`）最外层列表项各一条，有序、无序均可，嵌套列表、表格和代码块留在所属用例内。列表外说明作为共享背景展示，不另算用例；代码块中的列表不算用例。完整示例见上述文件。

CSV 首行为参数名，例如：

```csv
keyword,client
agent,dsh
testing,web
```

每个用例依次使用全部数据行，2 条用例和 2 行 CSV 展开为 4 个实例。`${keyword}` 等占位符按列名替换，支持重复引用，不执行表达式、不递归替换参数值里的占位符。CSV 支持带引号的逗号、换行和转义双引号；参数值保留前导零、空字符串和空格。空白行忽略，合法空字段记录保留。缺失参数列、重复/空表头、列数错误、无数据会在启动前提示；额外列保留供审核。

`/test-data` 始终进入原生 plan 模式。审核页列出原始命令、来源文件、原始用例数、CSV 数据行数、执行实例总数，以及每个实例的来源用例、数据行、所有参数、完整展开任务、拆分思路和步骤。模型不能删除或合并导入实例，也不能替你修改 CSV 值。可要求修改文字步骤并重新审核；更改用例文件或 CSV 后，应取消当前草案并重新提交，因为本次运行使用读取快照。

批准前不访问目标。批准后仍在同一对话逐实例串行执行，工具参数和定位留到当前步骤决定。报告按实例统计，支持按来源用例、数据行筛选；“用例来源与参数”展示对应原文、参数和展开任务。报告下载的计划保留完整输入快照；运行目录额外包含 `input.json`。原始 JSON 集合无需修改。

## 在当前对话查看执行过程

新建会话后可直接输入 `/test <任务与预期>`，无需先发送普通聊天。命令把真实任务提交给当前 Agent，会话由 DSH 正常保存和命名。执行过程就是普通对话：计划说明、浏览器调用、工具结果、审批、追问和最终总结均保留在本会话中。已完成工具可能按宿主默认行为折叠，可点击展开或查看“轨迹”。

`/test` 只把用户描述拆解为文字步骤和检查点，不在规划时指定工具、选择器、能力类型、输出Schema、字段路径或比较器。`/test-run <JSON路径>` 使用已审查的计划。测试模式只作用于发起会话，结束后撤销，普通后续聊天不受测试工具约束。其他新会话不会出现历史报告浮层。

使用原生“停止生成”或 `/test-stop` 停止业务动作；在途结算后，本会话会出现原生收尾轮次，执行冻结的清理，最后给出取消或错误结果及报告。不能证明在途结算时不运行清理，而是封存结果并隔离共享环境。

## 先审核再执行

```text
/test-plan GET https://httpbin.org/get?keyword=agent&client=dsh，断言HTTP状态码为200，响应body.args.keyword为agent，body.args.client为dsh
```

需要宿主已启用 `dsh-plan-mode` 和原生用户审核通道。插件通过官方 `commands.execute(agent, "/plan", ...)` 进入 plan 模式，仍在当前对话分析描述；规划阶段禁止浏览器、API和命令执行。

模型先用 `test_submit_plan` 保存草案，再通过原生 `exit_plan_mode` 展示“计划待审”卡片。点击“查看全文”审核业务短句及文字检查点；选择“要求修改”后在对话中输入修改意见，模型更新草案并重新展示审核。只有批准当前草案才冻结为 `plan.json` 并开始执行；直接关闭 plan 模式不能跳过审核。等待审核不计入执行超时，原生停止或 `/test-stop` 可以取消，取消前未执行则不派发清理工具。

`/test` 保持生成计划后直接执行。`/test-run` 保持直接执行已有 JSON 计划。三种入口都复用相同采集、断言、账本和报告链路。

## 文字规划与逐步执行

例如“访问ceshiren.com，搜索agent，打开第一条结果，断言点赞数不为0”可拆为：

1. 访问测试人社区。
2. 搜索 agent。
3. 打开第一条搜索结果。
4. 查看帖子点赞数，检查点赞数不为 0。

规划通报和审核卡片按“原始任务、拆分思路、步骤清单”展示。原始任务由插件保留，拆分思路用一两句说明动作顺序和检查目的，方便对照；不展开详细推理。网站结构、点击位置、请求参数、输出字段和比较器在执行到当前步骤时再分析，不要求用户提前知道未知页面细节。

模型用 `test_define_step` 设置当前步骤的能力和目标范围，不需要填写输出Schema；观察和操作页面后直接通过 `test_capture` 绑定采集位置，输出类型由采集方式自动登记。纯API可直接收集完整响应对象。当前步骤的每个文字检查点用 `test_bind_check` 关联可信观察和比较器，预期仍来自原文和文字清单。检查可以复用前一步观察，不重复发送请求。每项检查都要有程序计算结果，不能只口头判定通过。

原始文字计划保留在 plan.json，具体执行定义保存在实例的 effective_steps，账本记录 step_defined、capture_configured、check_bound。报告可展开“原始文字步骤与检查点”对照实际执行记录。`/test-plan` 审核文字后执行，`/test` 直接执行，已有 JSON 计划保持原格式。

## 纯接口测试示例

```text
/test-run examples/httpbin-get.json
```

示例向 [httpbin](https://httpbin.org/) 的 `/get?keyword=agent&client=dsh` 发送一次 GET，采集一个包含 HTTP 状态码和 JSON 响应体的观察，程序核对状态码 `200`、回显 `keyword=agent`、`client=dsh`。不调用 Playwright、不初始化浏览器，也不生成浏览器截图；附件保留 HTTP 原始响应，断言通过同一观察引用嵌套字段。当前接口采集支持 GET JSON，不支持 POST 或自定义请求体。

## 查看测试报告

最终回复会提供 **查看测试报告** 链接与完整保存位置，链接指向本机 DSH 的 HTTP 端口，可直接在浏览器查看。报告是静态 HTML：直接打开 `artifacts/runs/<运行ID>/report.html` 也能查看，不需要专门报告服务。复制整个运行目录可保留相对路径证据附件。

`/test-report` 不带参数只恢复当前会话的报告，绝不回退到另一个会话的“最近报告”；重启后也按报告 manifest 中的来源会话查找。指定 `/test-report <运行ID>` 可重建指定报告。原记录不被覆盖，重建写入 `report-rebuilt.html`。

网页访问复用 DSH 登录保护，服务关闭后 HTTP 链接不可用，但本地 HTML 仍可打开。无 Web 服务时保留本地路径。若通过远程代理访问 DSH，请将报告链接的本机地址替换为实际 DSH 地址，报告路径保持不变。

## JSON计划

完整示例见 `examples/ceshiren-agent.json`。一个 suite 含多个 case，每个 case 的 datasets 各自展开；例如两例分别2行和3行得到5个实例。空 datasets 自动产生 default 行。

准备、业务和清理复用 Step 结构；ID在同一用例跨阶段唯一，不得使用内部保留前缀 `__`。依赖只能指向前序；必需步骤不能引用可选输出。每例至少有一个必需业务断言。

动作必须声明目标URL、目标描述、输入、输出JSON Schema和必要输出。这些详细字段仅用于JSON执行计划；自然语言文字规划不需要填写。JSON默认使用固定capture，也可显式设置 `capture_mode: "runtime"`。输入支持 `{"input_ref":"data.inputs.key"}`、`{"resource_ref":"browser_context"}`、`{"literal":值}` 或直接JSON值。当前资源登记只支持独占的浏览器上下文。

`capture` 按输出名称定义可信采集：

| kind | 字段 | 行为 |
| --- | --- | --- |
| dom | selector、mode、可选index/attribute/field | 固定只读DOM函数；除显式index外必须唯一匹配 |
| http | url、field | 原生工具管线内执行HTTP GET并读取JSON，如 `body.amount` |
| browser_close | 无 | 通过Playwright MCP关闭上下文，以成功响应生成released=true |

DOM mode支持text、number、count、visible、url、attribute、value；url默认完整网址，field=pathname只取路径；index从0开始，用于明确的第几条结果。number只接受明确十进制文本，不把缺失/空白转换成0。缺少必要输出是ERROR；声明为非必要的输出缺失导致对应断言INCONCLUSIVE。观察槽只绑定一次，重复采集不覆盖旧值。运行时绑定调用 `test_capture({capture: {输出名: 采集定义}, reason: "当前页面依据或调整原因"})`；定位失败可调整后只补采缺失输出，不能更改输出含义、类型、目标范围或断言预期。

断言支持eq、neq、contains、range、exists、text、visible。预期在literal、data.expected引用、另一观察引用中恰选一种，规则必须有source_refs来源。neq保留类型要求，字符串"1"不会冒充数字1。range必须给单位、容差和两个数值边界。

## 动态检查、扩展与结果

模型可通过test_propose_checkpoint提交已有来源支持的追加断言，必须显式列出适用实例、required、插入边界和post_hoc。只允许向未终结实例的未来边界追加，不可改原步骤；新增来源、业务写动作或扩权需要重新提交经确认的计划。实例记录自身有效修订和必需集合，已结束实例不追溯改判。

其他插件沿用 DSH 官方事件、工具及审批扩展点；0.3.0 不再暴露旧独立执行器的 `testRunner.hook`。

报告按准备/业务/清理展示清晰步骤，包含实际/预期、来源操作数ID、工具调用、附件摘要。可按case、data和状态筛选。必要断言FAIL与必要清理ERROR会同时保留，主状态取ERROR。未开始的取消实例仍计入总数。

## 查看报告

报告默认打开“测试用例”：左侧按名称、用例、数据集和状态筛选，右侧切换步骤、断言和附件。步骤可展开工具调用和采集调整记录；断言中的“查看证据”跳转到本次实际响应或截图。概览按真实用例状态统计，并区分断言通过数与已执行数；取消、阻塞及未执行不会计为通过。运行信息包含起止时间、配置与原始数据入口。总耗时包含规划，步骤耗时为步骤时间之和，两者用途不同。

报告HTML内嵌截图预览与下载数据，页面交互不依赖网络或额外登录请求；截图可放大，响应可展开，事件账本以gzip压缩下载。原始附件仍保留在运行目录，便于独立核验。

明确的简单数字条件（如“不为0”“状态码为200”）在绑定断言时检查数值和比较器一致性，不能用数字字符串或不同预期替代。此检查不在规划阶段生成操作参数，也不是对任意自然语言的完整语义验证。

## 对话语言

模型面向用户的简短分析摘要、规划说明、步骤进度、工具调用说明、追问和最终结论，优先跟随 DSH 已保存的 `locale.preference`。宿主没有显式偏好（例如浏览器自动选择语言）时，沿用用户当前输入语言。当前中文任务默认简体中文，URL、代码、字段名和原始响应保留原样。插件通过宿主公开设置接口读取偏好，不修改 DSH 设置，也不改写历史消息。

常见断言预期在运行时直接填写原文，例如 agent 或 200，不需要 JSON 引号包装；类型由明确数字条件和可信观察确定。复杂对象或数组才使用 JSON。检查按文字清单的顺序结算，不能用动态追加检查覆盖尚未绑定的既定检查。
