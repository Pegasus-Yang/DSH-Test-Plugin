# 通用工具运行

插件 0.18.0 默认使用当前 DSH 对话已注册的业务工具。自定义 Selenium MCP 无需改成 Playwright 名称或返回包装；DSH 负责连接，插件负责计划、工具调用记录、实际值提取、断言和报告。

## 开始使用

1. 在 DSH 中配置并启用自己的 MCP 服务，确认当前对话能看到其工具与参数说明。
2. 打开“设置 → 测试插件 → 浏览器设置”，保留“自动使用当前可用工具”。需要优先使用某个服务时选择“指定主要 MCP 实例”；现有受管理 Playwright 和 RunBridge 连接继续可选。
3. 使用原有 `/test`、`/test-plan`、`/test-run` 或 `/test-data`。TXT、Markdown 和 CSV 不需要增加工具名称或内部采集字段。

例如一个计数页用例可以写成单个 Markdown 列表项：

```markdown
# 计数器按钮递增

- 打开本系统计数页，点击“增加 1”按钮一次，检查当前计数等于 1。
```

将“本系统计数页”替换成实际地址，再运行 `/test-run counter.md`。需要图片证据时，可在同一用例中补充“使用当前服务的截图工具记录页面”；没有截图工具而用例明确要求截图时，插件会保留未完成结果。

服务必须实际提供用例所需的操作或读取能力。工具名称、参数和返回结构由其真实 Schema 决定，不要求使用 `browser_*` 命名；模型根据工具说明选择具体调用，不需要用户逐项填写映射。

## 结果如何判定

插件会保存真实调用的响应，按执行前登记的定义提取字段，然后由程序比较实际值和原始预期。可以使用 MCP `structuredContent`、原生工具值、完整 JSON 文本、JSON 代码块或可确定提取的普通文本。模型不能直接填写实际值，也不能把“工具成功”当成业务通过。

提取字段缺失、类型错误或工具失败会保留异常。输出含义不清时保留未得结论，不会自动补造结果。自定义服务应提供准确的工具说明与稳定返回；程序可以核对调用和比较链，无法仅凭工具名称证明服务内部执行了什么。

HTML 报告继续使用统一执行过程，动作、检查与运行依据分开展示。手工 Markdown 保留成功操作、实际业务输入和原有预期，不包含观察调用和工具技术来源。来源字段与提取定义位于运行依据，便于复核。

## 截图预览与录像

工具返回的规范图片会归档为报告附件，无需 Playwright 截图工具。截图、实时预览和录像分别按实际能力提供；缺少可选媒体能力不阻断其他业务检查。

当前自动实时画面与录像仍复用既有 Playwright／CDP、Browscreen 接入，RunBridge 使用原有远程持续画面。其他 MCP 不会被自动注入 Playwright 启动参数；设置页会说明该连接没有自动媒体接入。指定主要 MCP 时媒体选择随同连接，不需要重复指定同一个实例。

## 上下文与收尾

自动模式默认由工具服务管理上下文，插件不先行重置或关闭用户已有会话。报告中的“由工具服务管理”不表示插件已确认该资源释放。用例要求登录前准备、干净环境或特定收尾时，应在原用例中明确写出；缺少必需能力时不能视为通过。

已有明确选择的 Playwright 连接继续初始化并关闭测试上下文。RunBridge 继续保留原 Node 的领取、整批共用、续租、归还与未知隔离规则。

需要插件管理自定义服务新建资源时，可在现有 `browserConnection` 中配置可选生命周期合同。以下示例对应测试服务 `managed` 模式提供的真实工具；其他服务按其实际名称和字段填写，不要求修改服务：

```yaml
browserConnection:
  backend: auto
  resourceLifecycle:
    scope: resource
    start:
      tool_name: mcp__selenium__create_context
      arguments: {}
    identity:
      from: structured
      pointer: /id
    identity_argument: context_id
    close:
      tool_name: mcp__selenium__dispose_context
      arguments: {}
    released:
      from: structured
      pointer: /released
      type: boolean
```

这是 `harness-test.config` 下的配置片段，不是用例文件。凭据仍由 DSH 的 MCP 连接配置提供。开始返回的真实 ID 由插件注入关闭参数，禁止预填另一个资源 ID；关闭结果必须明确为 `true`。每个实例创建与清理自己的资源。

服务只提供独立连接作用域时可以使用 `scope: connection`，省略身份提取和参数名；该模式只在原连接内处理收尾，重启后不自动关闭新连接。没有准确作用域或没有创建工具时，应继续使用默认外部管理模式。

创建或关闭结果未知时保留原记录和隔离，不重放创建请求，不换服务关闭新资源。恢复仅在原工具定义、连接配置摘要和明确资源身份均可核对时进行；否则使用已有设置页的实际处置证据入口。

## 旧配置与历史报告

已明确保存的 Playwright 或 RunBridge 选择继续生效；没有显式选择的默认配置使用自动工具模式。旧内部计划格式 1 和原有 DOM／HTTP 采集继续支持，新文字计划使用格式 2；用户无需修改 TXT、Markdown 或 CSV。

历史报告按原记录重建，未记录的操作、上下文身份或原始输入不会补造。0.17.0 的 Selenium 接入限制保留在[历史核验记录](../project/自定义SeleniumMCP兼容性核验.md)，新版本验收状态见[0.18.0 版本验收](../project/0.18.0版本发布验收.md)。
