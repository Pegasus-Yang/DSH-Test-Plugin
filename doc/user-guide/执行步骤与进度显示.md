# 执行步骤与进度显示

[项目首页](../../README.md) · [使用说明](使用说明.md) · [常见问题速查](../deployment/常见问题速查与处理.md)

以下截图来自 **0.11.2 的真实 GitLab 登录页检查**；当前步骤面板自 0.8.3 起提供。测试开始后，输入框上方显示进度面板，默认突出正在进行的操作。步骤多时，面板不会把所有节点横向铺开。环境准备与复杂用例见[GitLab 指导文档](GitLab测试要求与本地调试.md)。

## 一眼看清进度

面板上方显示运行阶段、任务名称和总耗时；进度条下方显示“已结算步骤 / 全部业务步骤”。中间显示当前步骤编号、操作文字、本步骤用时，以及存在时的下一步提示。

“已结算”包括通过、失败、错误、跳过和取消，不等于全部通过。准备与清理单独显示，不占业务步骤编号；业务步骤全部结算后，仍可能在清理资源。最终结果以报告为准。

多个用例或 CSV 数据实例的步骤按整个批次连续编号，当前区域同时标出“用例 2 / 3”等实例位置。

下图正在打开本机 GitLab 登录页：当前编号是 01，两步尚未结算，整轮用时和本步用时分别显示。

## 查看更多步骤

1. 点击“查看全部步骤（数量）”。列表保留整个批次的业务步骤，自动定位当前步骤。
2. 在列表内部滚动，查看较早或较晚的步骤。步骤数量增加不会把对话区无限撑高。
3. 点击某个步骤，可以展开完整文字、检查点和已记录的原因；再次点击即可收起。
4. 需要查看环境准备、资源清理或切换实例时，在列表底部点击“查看准备、清理及完整详情”，打开原生侧边栏。
5. 点击“收起完整步骤”关闭列表。面板展开时右上角显示向下箭头，点击可收起整个正文；收起时变为向上箭头，点击可重新展开，运行阶段、总耗时和结算进度仍保留。

折叠或查看详情不会停止测试，也不会重新执行步骤。再次打开正文时可以继续查看原来的列表。

下面是两步业务都已结算时的完整列表。各行保留步骤文字、状态和耗时；业务结算后仍可能等待收尾和最终通报，底部入口可以继续查看准备、清理和完整详情。

![GitLab 两步业务已结算的完整列表：步骤状态、耗时和完整详情入口](images/GitLab完整步骤.png)

界面没有增加固定的步骤数量上限。已用真实页面的模拟快照验证 100 步列表，用展示模型验证 1000 步的编号和定位；这些是 UI 验证，不代表已经执行同规模的正式业务用例，也没有改变执行预算或共享环境的串行规则。

## 长文字和小窗口

任务标题最多显示两行，完整标题可在详情页查看。当前操作默认最多两行；确实超出时出现“展开完整文字”，展开后仍可在限定区域内滚动，避免遮住输入框。长网址可以换行。

窄容器中，编号、文字和耗时会重新排列；短窗口中，面板和列表的滚动高度会收紧。键盘可以操作折叠按钮、步骤条目和文字展开按钮，焦点有清晰边框。

## 其他入口

| 入口 | 何时出现与用途 |
| --- | --- |
| 显示实时画面 / 隐藏实时画面 | 当前运行提供有效预览时出现；切换 DSH 原生画面浮窗的显示与隐藏，同一对话最多一个 |
| 测试报告 | 运行提供报告链接后出现；查看真实结果及证据 |
| 重建报告 | 运行结束后出现；根据账本重新生成报告，完成后点击“查看重建报告” |
| 连接暂不可用 | 读取进度失败时显示；保留上一次数据并暂停本地耗时增长，连接恢复后更新 |

规划中没有确定的业务步骤时，显示“业务步骤尚未确定”；等待审核不显示假装执行中的第一步。失败或中断有文字及警示图标，取消记录不会显示成通过状态。

耗时包含规划、工具执行及等待；总耗时和单步用时的起点不同，不要求两者简单相加。实时画面的 CDP 与首帧要求、环境隔离和报告规则保持原样，详见[预览配置](浏览器实时预览一步一步配置.md)和[环境处置](测试环境卡住怎么办.md)。
