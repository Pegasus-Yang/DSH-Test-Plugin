# Installation and deployment

[简体中文](安装与运维.md) | English · [Project README](../../README.en.md) · [User guide](../user-guide/使用说明.en.md)

These instructions target plugin 0.8.0 and a local DSH Web profile. They describe building from a checkout, installing the bundle, configuring tools, upgrading, and recovering the test environment.

## Prerequisites

| Component | Supported or verified configuration |
| --- | --- |
| Node.js | Minimum 22.19; tested with 22.22.3 |
| pnpm | Project pins 11.7.0 |
| DeepSeek Harness | Locally built `0.2.1-alpha.1`; acceptance used commit `5badb15009ae1756c3afe0ae0cef1faafc290ccc` |
| Model | A working model route and credentials configured in the target DSH profile |
| Tool mode | `native`; one tool call at a time for this test flow |
| Browser tools | `@playwright/mcp` 0.0.68, with the matching Chromium installed by the helper |

The tested MCP browser was Chromium 146.0.7680.0, revision 1212. MCP and the report-validation dependency may resolve different Playwright versions; the browser installer handles both. A dedicated isolated Chromium context avoids interfering with your personal browser. API-only tests do not require a browser or MCP.

Install and build DSH using its own instructions first. This plugin's build does not build the host. A different host or MCP version requires renewed compatibility checks, including approval, stop, and cleanup behavior.

## Build and package

From the plugin checkout, replace the paths below:

```sh
cd /absolute/path/DeepseekHarnessTestPlugin
pnpm install
node scripts/link-host.mjs /absolute/path/deepseek-harness
pnpm typecheck
pnpm build
pnpm test:unit
pnpm test:integration
pnpm pack --out artifacts/package/dsh-test-plugin.tgz
```

The link helper connects development imports to already-built local host packages and saves `.local/host.json`; it does not modify host sources. The archive contains `dist`, both root READMEs, user/deployment documentation, examples, licenses, bundle patch, icon, and localization metadata. Host packages are peer dependencies supplied by DSH. Source-checkout helpers are not part of the deployment archive.

### Build fails with TS2307 for DSH modules

If type checking or building reports `Cannot find module '@deepseek-ai/…'` followed by errors such as implicit `any`, check the local host links first. `.local/host.json` records a path; it does not prove that links under `node_modules/@deepseek-ai/` still exist. Run the link step again after reinstalling dependencies or rebuilding `node_modules`:

```sh
node scripts/link-host.mjs /absolute/path/deepseek-harness
pnpm typecheck
pnpm build
pnpm pack --out artifacts/package/dsh-test-plugin.tgz
```

The helper does not build DSH. If modules or declarations remain missing, install and build the host using its own instructions before retrying. Keep strict type checking enabled and do not substitute fake declarations or old build output. This project's `pnpm pack` does not run the build; confirm that `pnpm build` succeeds first.

For browser tests, run from the plugin checkout:

```sh
node scripts/install-browser.mjs
```

This installs browser binaries for the pinned MCP and validation Playwright dependencies. Keep the checkout's MCP dependency available at the configured path; the plugin archive itself does not bundle Playwright MCP.

## Install into the existing web profile

From the DSH source checkout:

```sh
cd /absolute/path/deepseek-harness
pnpm dsh plugin --profile web add /absolute/path/DeepseekHarnessTestPlugin/artifacts/package/dsh-test-plugin.tgz
```

A standalone `dsh` installation can use `dsh plugin ...` instead. Without `DSH_HOME`, this affects the user's default DSH home. For a custom home, use the same value for installation and startup, for example:

```sh
DSH_HOME=/absolute/path/custom-dsh-home pnpm dsh plugin --profile web add /absolute/path/DeepseekHarnessTestPlugin/artifacts/package/dsh-test-plugin.tgz
```

A separate home needs its own working host/model configuration. Installation alone does not copy credentials from the default home.

The official command adds the package to the profile's dependencies and `dsh.profile.bundles`. The bundle's `cordis.patch.yml` registers `harness-test`. Its absence from the user-written profile patch does not mean the plugin is missing. Do not add another instance of the same plugin.

Keep the archive at its installed path: it remains the source of a local `file:` dependency. Use the stable filename `dsh-test-plugin.tgz` for subsequent builds. Only remove an old archive after successfully migrating the profile away from its path.

## Configure the installed plugin

From the plugin checkout, create the local configuration directory:

```sh
mkdir -p .local
```

Save this as `.local/dsh-test.patch.yml`, replacing paths with real absolute paths. It updates the plugin already registered by the bundle and adds a dedicated MCP. If you already have a dedicated MCP named `playwright`, reuse that entry instead of registering another. Omit the entire `insert` section for API-only testing.

```yaml
- id: tools
  config:
    mode: native
- id: agent-loop
  config:
    maxParallelToolCalls: 1
- id: harness-test
  config:
    workspace: /absolute/path/DeepseekHarnessTestPlugin
    outputRoot: /absolute/path/DeepseekHarnessTestPlugin/artifacts/runs
- insert:
    - id: test-playwright
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: playwright
        transport: stdio
        command: node
        args: ['/absolute/path/DeepseekHarnessTestPlugin/node_modules/@playwright/mcp/cli.js', '--headless', '--browser', 'chromium', '--isolated']
        toolCallTimeoutMs: 60000
        failOnStartupError: true
```

`node` must be available to the host process; use its absolute executable path if necessary. Browser tool names must start with `mcp__playwright__`. Do not share this browser context with simultaneous work in another conversation.

`workspace` controls the allowed JSON-input directory. `outputRoot` controls records, reports, and quarantine state. Selecting a directory in the Web UI does not replace these plugin settings. Keep `outputRoot` stable across restarts.

| Setting | Default | Meaning |
| --- | --- | --- |
| `workspace` | Host process working directory | Suite and remediation files must stay inside it |
| `outputRoot` | Absolute `artifacts/runs` relative to process working directory | Run records, reports, and quarantine markers |
| `stepTimeoutMs` | `180000` | Step time budget, including tool approval waits, in milliseconds |
| `cleanupTimeoutMs` | `60000` | Cleanup-step budget including approvals, in milliseconds |
| `cancelGraceMs` | `10000` | Time allowed for in-flight operations to settle after cancellation |
| `maxRevisions` | `10` | Maximum appended-check revisions per run |

Timeouts must be finite positive values. The output directory must be writable; a write failure stops further work rather than being reported as success. Model selection and routing remain the current agent's responsibility.

## Start and verify

Version 0.8.0 adds **Settings → 测试插件 → 浏览器实时预览**. Prepare Browscreen's `.venv` with uv, enable preview, enter its absolute project directory and an unused capture port (normally 13390), select the dedicated local Playwright MCP, and click 保存设置. On the next test, the plugin preserves existing MCP arguments, environment, JSON configuration and initialization scripts while adding its CDP initializer and shared directory. It starts Browscreen only after usable CDP exists, and opens the floating panel only after a valid first frame. API-only and no-CDP tasks remain unaffected. See the [step-by-step guide (Chinese)](../user-guide/浏览器实时预览一步一步配置.md).

Register the MCP in the editable Web profile (`~/.dsh/profiles/web/cordis.patch.yml` by default), with `serverName: playwright`, local `stdio` transport and Chromium. A command-line or home overlay that fixes this plugin or MCP configuration prevents profile edits; move those related entries into the profile instead of stacking another overlay. The current auto-setup does not handle remote HTTP MCP, extension mode or externally connected browsers. Existing MCP versions are preserved, not upgraded.

Preferences are stored under `harness-test.config.browserPreview`. Saving does not restart the test plugin or reconnect MCP immediately; the next `/test`, `/test-plan`, `/test-run`, or `/test-data` reads the new values. The first setup may reconnect the selected MCP, so dedicate it to this test flow. Refreshes and normal host restarts preserve preferences. Installing a new plugin version still requires a host restart and page refresh.

When no debugging port is configured, setup adds `--remote-debugging-port=0` so the OS assigns one. The initializer reads the actual port from the current browser's DevToolsActivePort file, located through its public command line. Real CDP/Browscreen checks passed with MCP 0.0.68 and 0.0.80; users never need to guess a CDP port.

The older manual `preview.workDir`, `preview.browscreenUrl`, and `preview.browscreenProject` setup remains supported when no new `browserPreview` preference has been saved. Once saved, the new preference takes precedence, including an explicit disabled value. See the [manual configuration example (Chinese)](安装与运维.md#浏览器实时预览可选).

No extra preview prompt is required: continue using `/test` or `/test-plan`. With a Browscreen project configured, no separate capture-service startup is needed. Finished runs cannot reopen live frames, and enabling preview does not release an existing resource quarantine. Installing the package alone does not enable preview or change an existing MCP configuration.

The development launcher detects a sibling Browscreen checkout, uses a preview directory per DSH port, and assigns Browscreen the next port. Set `DSH_BROWSCREEN_PROJECT` to another checkout or `DSH_TEST_PREVIEW=0` to disable preview. Custom `DSH_TEST_STATE` paths also separate logs and overlays.

For settings-page verification, combine `DSH_TEST_SETTINGS=1` with `DSH_TEST_PREVIEW=0`: the development launcher places its test plugin and MCP in the editable isolated profile. It never modifies the default user profile.

From the DSH checkout, use an available port and preserve any other host options you need:

```sh
pnpm dsh web --patch /absolute/path/DeepseekHarnessTestPlugin/.local/dsh-test.patch.yml --port 3080
```

Add the same `DSH_HOME` prefix if you installed into a custom home. If a server is already running, stop it normally before restarting with this configuration. Open the access address printed by the host and select the test workspace using the standard agent preset.

Verify installation in a new conversation:

```text
/test-plan Send a GET request to https://httpbin.org/get?keyword=agent&client=dsh and verify HTTP status 200, keyword agent, and client dsh in the response.
```

Confirm that the native plan-review card appears before any request. Approve the plan and inspect the final assertions and report link. For UI testing, use the [browser example](../user-guide/使用说明.en.md#browser-example). Successful packaging or command registration alone is not end-to-end acceptance.

`/test-plan` requires the preset's native `/plan` command, `exit_plan_mode`, and user-review channel. The standard Web preset provides them. The plugin enters plan mode through the official command interface rather than accessing the isolated service directly. Custom presets without this capability can still use `/test` and `/test-run`.

## Upgrade and uninstall

Rebuild the plugin and pack to the same stable filename. With pnpm 11.7.0, replacing an archive at the same path without changing its version was observed to retain old installed files despite a successful command. For development updates, remove the dependency and add the new archive sequentially:

```sh
pnpm dsh plugin --profile web remove dsh-test-plugin
pnpm dsh plugin --profile web add /absolute/path/DeepseekHarnessTestPlugin/artifacts/package/dsh-test-plugin.tgz
```

Restart the host for that profile and refresh the page to load the new code. Keep the source archive available. You do not need to remove conversation history or rewrite old run records; `Already up to date` alone does not prove the new build was installed.

To uninstall the plugin from this profile:

```sh
pnpm dsh plugin --profile web remove dsh-test-plugin
```

Also remove the `harness-test` override from any startup patch you supplied, then restart. Remove the dedicated MCP entry only if it is no longer used. Removing the package is not a request to delete saved reports, conversations, or other plugins.

### Recover from a deleted package path

If you are adding `dsh-test-plugin.tgz` but ENOENT names an old archive such as `dsh-test-plugin-plan-review.tgz`, the profile manifest and lockfile still reference the old `file:` source. With the tested pnpm 11.7.0 configuration, dependency updates can try to read that deleted archive before completing the replacement. This is a package-management failure, before plugin loading.

Make sure the new archive exists, then run these official commands sequentially from the DSH checkout:

```sh
pnpm dsh plugin --profile web remove dsh-test-plugin
pnpm dsh plugin --profile web add /absolute/path/DeepseekHarnessTestPlugin/artifacts/package/dsh-test-plugin.tgz
```

Use the same `DSH_HOME` on both commands if applicable. `remove` clears the stale dependency and bundle registration; `add` installs and registers the new bundle. There is no need to restore an old filename, hand-edit the lockfile, delete the profile, or clear the package-manager cache. Restart the matching host and refresh its page after successful installation.

## Isolated development environment

The following helper is for this source checkout, not for deploying a downloaded archive. After dependency installation, host linking, build, and browser installation, run from the plugin root:

```sh
node scripts/start-host.mjs
```

By default it loads local `dist/index.js`, creates `.local/dsh-home`, and starts the host's built `apps/cli/lib/bin.js` on port 13379. It reads `.credentials.yaml` references and the `llm-pi-ai` / `agent-default-model` entries from an existing source home's Web patch. It does not copy every possible model configuration or inline credential record; configure the host normally if your setup differs.

| Environment variable | Purpose |
| --- | --- |
| `DSH_CREDENTIAL_HOME` | Source home for the helper's model settings and credential references; default `~/.dsh` |
| `DSH_TEST_HOME` | Isolated home used by the helper; default `.local/dsh-home` |
| `DSH_TEST_PORT` | Listening port; default `13379` |
| `DSH_TEST_OUTPUT` | Run output path; default `artifacts/runs` |
| `DSH_TEST_INSTALLED=1` | Use the bundle already installed in the isolated home instead of inserting local `dist` |
| `DSH_MCP_TRACE=1` | Record MCP message IDs, names, sizes, and timing without message bodies |

The helper writes local state and logs under `.local`. Its authenticated URL is in `.local/host-state.json`; do not publish it. To stop only the helper's recorded host process tree:

```sh
node scripts/stop-host.mjs
```

It saves `.local/reset-proof.json`. Inspect the outcome before using that file as remediation evidence. `DSH_TEST_STATE` and `DSH_TEST_PROOF` can override the state/proof paths. This script is not a general service shutdown tool.

## Stop, cleanup, and quarantine

Native Stop or `/test-stop` prevents new business work. After in-flight tools settle, the originating conversation performs only frozen, preauthorized cleanup. If settlement or browser release cannot be confirmed, the plugin persists quarantine; restarting does not clear it. Late results remain audit data and do not rewrite the final outcome.

Before releasing quarantine, verify external work has stopped and reset the affected environment. Create a JSON file inside the configured workspace describing actual remediation:

```json
{
  "operator": "Your name",
  "external_stopped": true,
  "environment_reset": true,
  "details": "Describe what was stopped, reset, and checked",
  "evidence": {"log": "path/to/the-actual-verification-log"}
}
```

Then enter `/test-release path/to/resolution.json` in DSH. Replace the sample content with real evidence; do not set flags to true without checking, and do not delete `quarantine.json` manually. The command records your verified remediation statement; it cannot perform that external verification for you. Interrupted runs are not automatically resumed after a host restart.

## Reports and deployment boundaries

Web access uses the host's optional Web server and connection services. `/test-reports` serves report files using the same login protection, without an extra port. Reports are static HTML, with embedded previews and downloads, and remain viewable offline. HTTP links require the DSH service to be running. Without the Web services, the plugin still provides a local file path.

Generated URLs currently use `127.0.0.1` and the host port. For remote/proxy access, use your real DSH origin with the same report path and normal authentication. Do not publish credential-bearing host URLs. Screenshots are not automatically visually redacted; inspect report contents before sharing them.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| A test command behaves like ordinary chat | Verify installation in the profile/home being served; restart and refresh after upgrade; provide the command's arguments |
| JSON example cannot be found | Resolve the path under plugin `workspace`; copy the example there if necessary |
| Browser tools are missing | Check the dedicated MCP startup log, `node` path, installed browser, native tool mode, and `mcp__playwright__` prefix |
| Plan review is unavailable | Use the standard Web preset or configure the native plan/review services in the custom preset |
| HTTP report link fails | Check host availability and login; for remote use, correct the origin, or open the local HTML |
| The environment remains blocked after restarting | Inspect the recorded quarantine reason and complete verified remediation before `/test-release` |
| Progress is not visible after completion | Expand DSH's collapsed tool messages or use its trace view |

Use [the user guide](../user-guide/使用说明.en.md) for command behavior and [the acceptance record (Chinese)](../project/开发进度.md) for the actual tested scope.
