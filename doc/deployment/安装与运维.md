# 安装与运维

## 锁定环境

开发/实测使用 Node.js 22.22.3、pnpm 11.7.0、本地 DeepSeek Harness 0.2.1-alpha.1（提交5badb15009ae1756c3afe0ae0cef1faafc290ccc）、Playwright MCP 0.0.68、匹配的 Chromium 146.0.7680.0（revision 1212）。仅支持native工具模式，同批最大并发1。MCP自己的Playwright依赖由锁文件确定，与报告验收脚本使用的Playwright版本分别记录。

使用 `node scripts/install-browser.mjs` 安装MCP自身锁定的浏览器版本，不与验收脚本的Playwright版本混用。系统Chrome在本机曾因更新器继承输出管道导致browser.close迟迟不结算；测试MCP因此采用独立Chromium，不修改系统浏览器。

首次开发按README安装依赖并执行link-host；该脚本只在插件项目内链接宿主已构建的包，不修改宿主。start-host为开发辅助脚本，读取本机已有模型配置；没有配置时请先在Harness中设置模型，不要把密钥写进示例或Git。

## 配置

原生插件patch示意，路径替换为部署环境的实际路径：

```yaml
- id: tools
  config:
    mode: native
- id: agent-loop
  config:
    maxParallelToolCalls: 1
- insert:
    - id: test-playwright
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: playwright
        transport: stdio
        command: node
        args: ['/绝对路径/node_modules/@playwright/mcp/cli.js', '--headless', '--browser', 'chromium', '--isolated']
        toolCallTimeoutMs: 60000
        failOnStartupError: true
    - id: harness-test
      name: dsh-test-plugin
      config:
        workspace: /测试工作区
        outputRoot: /测试工作区/artifacts/runs
```

为测试使用专用MCP实例；运行期间不要在其他会话共享操作该浏览器。工具名必须采用mcp__playwright__前缀；更换MCP或宿主版本后需重验返回格式、早退、审批、取消和清理。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| workspace | 进程工作目录 | JSON输入必须在该工作区内 |
| outputRoot | artifacts/runs绝对路径 | 运行数据与隔离标记；重启必须保持不变 |
| stepTimeoutMs | 180000 | 业务动作和审批等待共同上限，毫秒 |
| cleanupTimeoutMs | 60000 | 每个清理动作及其审批的上限 |
| cancelGraceMs | 10000 | 取消后等待在途结算的独立期限 |
| hookTimeoutMs | 5000 | 单个hook期限 |
| maxModelSteps | 24 | 每动作模型轮次上限；最多两次补充提示 |
| maxRevisions | 10 | 一个批次最多10次动态修订 |

所有预算为有限正数。实际采用值写入运行manifest。输出目录需可写；写入错误停止新动作，尽力保存emergency.json，不把错误报告成成功。

## 构建与打包

```sh
pnpm typecheck
pnpm build
pnpm test:unit
pnpm test:integration
pnpm pack --out artifacts/package/dsh-test-plugin.tgz
# 使用公开DSH profile插件入口安装
DSH_HOME=/隔离的dsh-home dsh plugin --profile web add /绝对路径/artifacts/package/dsh-test-plugin.tgz
```

包内只包含dist、使用/部署文档、README、许可证和示例；宿主模块为peer依赖，由相同版本的Harness提供。正式发布前须查阅开发进度中打包安装的实测结论，不把构建成功等同于干净环境安装成功。

## 停止与隔离处置

/test-stop禁止后续业务派发，在途全部结算后启动独立清理会话。清理中也可使用原生审批。收尾超限、必要资源清理未完成或重建发现未结算调用会持久隔离；重启不会自行解除。迟到结果仅审计，不回改结果。

解除前必须核实外部动作停止、重置受影响环境并记录证据。项目内创建处置JSON：

```json
{
  "operator": "实际操作者",
  "external_stopped": true,
  "environment_reset": true,
  "details": "实际检查和重置过程",
  "evidence": {"日志或截图路径": "实际位置"}
}
```

执行 `/test-release 相对路径/处置.json`。插件保存release审计文件后解除门禁。该命令接受操作者对实际处置的声明，不能替代外部检查；不得为了继续测试虚填true或直接删除quarantine.json。重启恢复识别已处置运行的审计记录。

开发脚本 `node scripts/stop-host.mjs` 默认仅停止 `.local/host-state.json` 所记录宿主及其进程树，保存 `.local/reset-proof.json`；可用 `DSH_TEST_STATE`、`DSH_TEST_PROOF` 指定本任务另一隔离宿主状态与处置文件；它不是通用生产运维接口。调试代理 `DSH_MCP_TRACE=1` 只记录MCP消息ID、名称、大小和时间，不记录消息正文。调试文件全部忽略，不进入包或Git。

报告可整体复制；路径为相对附件路径。JSONL中间损坏拒绝重建，尾部损坏标记中断。原始报告和记录保持原貌；重建写入独立文件。截图没有自动视觉脱敏，分发前按实际页面内容检查。
