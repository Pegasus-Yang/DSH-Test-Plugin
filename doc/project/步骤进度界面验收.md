# 步骤进度界面验收

日期：2026-10-04。版本：0.8.3（开发版本）。采用用户选定的第 3 种设计：天蓝色当前步骤面板，完整步骤按需展开。使用方法见[执行步骤与进度显示](../user-guide/执行步骤与进度显示.md)。

## 实现范围

- 面板与原生输入框同宽；显示阶段、标题、总耗时、结算数量和进度条。
- 默认突出当前步骤编号、操作、本步用时和下一步；多实例业务步骤连续编号。
- 完整列表覆盖整个批次，自动定位当前步骤；点击条目查看检查点和原因，底部打开既有详情侧边栏。
- 支持整体折叠、长文字展开、长网址换行和限定区域滚动；窗口变化后重新定位当前步骤。
- 规划、审核、准备、清理、结束、取消和异常使用各自的描述。已结算不等于通过；资源动作不占业务编号。

展示规则在 `src/client/progress-view.ts`，面板交互在 `src/client/progress-dock.tsx`。沿用现有轮询、按会话关联、预览和报告接口，不修改执行预算、工具、审核、释放或并发行为。图标使用宿主 `@deepseek-ai/dsh-client-ui-primitives` 共享模块，开发包将其声明为可选 peer；实际宿主为 `0.2.1-alpha.1`。

## 验证及证据边界

TypeScript 构建通过；单元及集成 **146 项、17 个测试文件**通过。新增8项展示模型检查涵盖1000步、重复步骤ID的多实例、0/1步、资源动作、失败、取消和中断。

UI 验证使用真实本机 DSH 和本次前端代码，服务器以独立插件提供模拟进度快照；端口13421、独立 home/profile，不调用模型或业务工具。模拟可用预览只验证原生浮窗打开和关闭，画面中明确标注没有连接真实 CDP。它不替代已有真实浏览器首帧、CDP、API无浮窗及正式用例验收，也不说明已经执行100或1000步的业务测试。

## 视觉修复

同屏比较发现字体及编号区域偏小，已调整关键字号、编号尺寸和分隔间距。短窗口展开列表时曾让发送按钮超出视口，已收紧正文及列表高度；缩窄窗口曾使当前行偏离可见区域，已监听实际尺寸重新定位。修复后重新截图，未留下 P0/P1/P2。保留宿主输入框、字体与原生图标；按当前展开状态使用箭头方向。
