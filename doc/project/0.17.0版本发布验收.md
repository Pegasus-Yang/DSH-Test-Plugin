# 0.17.0 版本发布验收

## 目标与范围

2026-10-31 将 DSH 支持集合从 alpha.1～3 扩展至 `0.2.1-alpha.1`～`alpha.5`、`0.2.1-rc.1`～`rc.5`，共 10 版。版本范围按 [npm 官方记录](https://www.npmjs.com/package/@deepseek-ai/dsh?activeTab=versions) 和[官方发行标签](https://github.com/deepseek-ai/deepseek-harness/releases) 核对；`0.2.2-alpha.2` 不在本次范围。

插件版本、运行 manifest、当前中英文安装指南和本地附注标签统一为 `0.17.0`。构建 SDK 保留 alpha.3，全部 22 个 DSH peer 由 `dsh-compatibility.json` 同步。CI 自动生成全部支持宿主矩阵，发布门禁要求所有宿主通过。

## 相关调整

使用 rc.5 公开 SDK 的真实 `evaluatePluginCompatibility`，将已发布 `v0.16.0` 的原清单与新清单分别传入 alpha.4、alpha.5、rc.1～5 目标版本：原清单每版均因 22 项 peer 范围不匹配被拒绝，新清单全部准入。此对照复现声明导致的安装问题；实际独立宿主安装和业务结果另按逐版矩阵记录。

- 新宿主的准入检查返回 `requirements`，旧宿主返回 `peers`；验证器兼容两种字段，并逐项核对范围外宿主被拒绝的依赖。
- 同批 SDK 环境显式安装插件使用的公开 DSH 开发 SDK，版本从对应官方标签读取；宿主未自动安装的客户端类型依赖也参与完整类型回归。公开用户安装仍独立验证，不施加这些约束。
- 插件 profile 不包含第二份宿主 SDK，不使用版本豁免，也不新增运行时版本分支。
- 本轮验证页面使用 1440 × 900；此前报告截图来源仍为真实的 0.16.0 运行，不改写历史来源。

## 发行候选包

唯一候选包 SHA-256：`a9653e3b121e0e2567077bb9990770d4970b4a71da9fa94224e7e43b66253acb`。包内为 0.17.0，包含 178 个文件、113 个 dist 文件、全部 10 版策略及 22 个一致的 DSH peer；不含本机配置、凭据或宿主 SDK。

独立源码副本中冻结安装通过，没有外部宿主链接；以 alpha.3 构建 SDK 重建的全部 113 个 dist 文件与候选逐字节一致，真实宿主入口导入通过。本机单元／集成回归 516 通过、0 失败／跳过，浏览器首次引导专项 8 通过。

解包后的 177 个普通文件与当前源码／文档逐字节一致；包清单仅省略开发用的 `packageManager` 字段，其余字段完全一致。解包后的入口完整性和版本检查通过。

## 预检与保留的失败

首次浏览器运行在 macOS 沙箱内因 Chromium MachPort 权限被拒绝，alpha.4 和 rc.5 的预检在 Web 启动处停止，两个验证宿主都已退出。随后使用允许启动浏览器的环境重新验收；该失败属于本机执行权限，不作为宿主不兼容的结论。

初始 SDK 类型探针未显式安装客户端类型依赖，出现缺少 `dsh-client-ui-slots`、`dsh-client-ui-primitives` 的错误。按目标发行标签补齐同批公开 SDK 后，alpha.4 和 rc.5 类型检查通过；正式矩阵使用修正后的准备流程，不以忽略类型错误或混用构建 SDK 代替验证。

alpha.1、alpha.4 在网页测试后的同会话 `/test-run api.md` 分别触发一次模型“确认任务／意图”原生问答。验收人员选择“按 api.md 提交测试计划并执行”或“按文件中的用例规划并执行测试”后继续，未修改用例、预期或执行策略。这两轮保留原生问答及各一次人工澄清记录，不表述为完全无人干预通过；其他版本按各自实际记录统计。

## 验证层次与边界

各宿主独立安装公开 npm 发行版，并通过实际 CLI 安装同一 tgz。公开安装检查实际解析；同批环境核对对应标签的全部 SDK 版本后运行类型、单元和集成回归，再验证真实 Web 设置保存、重启回读、停用、启用、卸载及进程停止。

本机调度从 3 并行扩容为 6 并行，SDK 重回归继续串行。扩容时 alpha.5、rc.2、rc.3 的原验证进程继续运行，三者均保留 macOS `ps xstat=0`、完整 PASS 摘要和清理记录；三者结束后停止旧调度器，其退出 137 属于调度切换记录。新调度器负责最终汇总，各宿主退出状态分别核对。

正式交付同时执行受控真实模型、Playwright MCP 和 GitLab Markdown UI／接口回归；预期来自固定夹具和种子。每轮完成后等待 Agent 空闲、测试作用域关闭、在途调用归零，再继续下一轮。每版使用独立 GitLab 准备记录，完成后只清理对应测试项目并核对认证 GET 返回 404。

本机结果属于 macOS arm64、Node.js 22.22.3 的验证；不能替代推送后 GitHub 托管 Ubuntu 的实际 CI 结果，也不扩大 RunBridge 实机或 Browscreen 录像的历史验证范围。本轮不推送提交、标签，不创建远端 Release；用户审核后推送 `v0.17.0` 才触发自动发布。
