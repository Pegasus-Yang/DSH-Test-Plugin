# 预览设置与自动接入验收

日期：2026-10-04。插件版本：0.8.0（开发版本）。本轮实现 DSH 设置页、偏好持久化、下一次测试读取与 MCP 自动接入，并补充[带截图的逐步指南](../user-guide/浏览器实时预览一步一步配置.md)。保留原有 CDP/有效首帧门禁，不修改 DSH 或 Browscreen 核心。

## 实现行为

- “设置 → 测试插件”提供启用开关、Browscreen 目录、采集端口和兼容 Playwright MCP 选择；通过原生 configForms 保存到当前 profile。
- 保存不重载正在执行的测试插件，不提前重新连接 MCP。新测试开始前读取整组 volatile 偏好；启动准备也保持共享环境互斥。
- 自动生成 CDP 初始化配置和共享目录，保留 MCP 命令、版本、其他参数、已有环境变量、JSON 浏览器配置与页面初始化脚本。重复准备参数稳定，采集端口修改不要求 MCP 重新连接。
- 未保存新偏好时沿用旧 `preview`；保存后新设置优先，包括明确关闭。错误停用展示并给出原因，不修改业务断言或解除隔离。
- Firefox/WebKit、远程 HTTP、扩展和外部 CDP 连接不属于本次自动接入；命令行/home overlay 固定相关配置时，沿用宿主的拒绝规则。

构建及 TypeScript 检查通过。单元与集成检查合计 121 项通过；首次全量执行暴露旧进度客户端替身缺少新增的可选 `ctx.inject`，补齐替身后重跑该文件通过。新增检查覆盖配置引用与非法端口、旧配置兼容、用户参数保留、重复准备、延后接入与关闭、MCP 缺失、非 Chromium 拒绝和启动准备互斥。

## 验证边界

真实界面覆盖保存、刷新、首帧条件、连续画面、API 无浮窗和结束释放。配置修改期间不重载插件及下一次读取的规则由 volatile 接口、准备互斥和定向测试共同覆盖，本轮没有额外启动模型用例来重复验证每个字段组合。

当前用户正在使用的普通 Web profile 未被本轮验证脚本修改。升级安装后仍需正常重启宿主并刷新网页，再在设置页启用。共享环境存在隔离标记时仍必须完成原有处置流程。

开发源码路径需使用 Loader 规范化后的 file: URL，才能由 config-editor 正确定位配置；开发脚本的设置验收模式已处理。普通安装包使用稳定包名，不受该源码路径差异影响。高优先级 overlay 的拒绝与源码路径差异均在真实设置验证中发现，没有修改宿主来绕过限制。

0.0.80 不再默认提供独立 CDP 监听端口。自动接入在未指定调试端口时补充 `--remote-debugging-port=0`，由系统分配；初始化扩展经当前页面公开的 Browser.getBrowserCommandLine 得到临时目录，读取该浏览器 DevToolsActivePort 的实际端口。不扫描其他浏览器，不猜测固定端口。0.0.68 与 0.0.80 均已通过真实 CDP/Browscreen 小验证，0.0.80 另有原生 `/test` 页面导航、可信 h1 采集与浮窗验证；其全部工具、审批和多标签行为不在本轮重新验收范围内。
