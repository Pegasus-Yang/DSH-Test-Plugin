# GitLab 复杂用例验收

> 发布记录：相关实现已纳入 0.11.0，见[版本发布验收](0.11.0版本发布验收.md)。以下保留实施阶段的版本、运行结果和未发布状态，不改写原始失败或验收事实。

验收日期：2026-10-06。被测系统为本机 GitLab 19.4.1；执行宿主为公开 npm DSH 0.2.1-alpha.1，插件代码基于本地主分支 0.10.0，Playwright MCP 0.0.68。使用独立 DSH profile 和工作区；没有修改用户日常 DSH profile 或 GitLab 实例配置。

## 交付范围

- 4 条复杂 UI 场景、13 条纯接口场景，共 100 个必需业务检查点。
- 从被忽略的 .local/gitlab/config.json 读取登录输入，按次生成私有 JSON 集合及单场景文件。
- 准备独立的 UI 项目和接口基线项目，固定 Issue、标签、状态、评论及预期。
- 按账号、个人命名空间、本次标记、精确路径及 ID 清理专用项目；处理创建响应丢失、延迟删除和删除重命名。
- 不增加斜杠命令，不扩展插件的 HTTP 方法或认证能力。准备/清理的写接口不算 DSH 接口用例执行。

## 自动检查

公开 SDK 的类型检查、构建和发行入口检查通过。单元测试 225 项、原生生命周期集成测试 43 项，共 268 项通过。

新增 17 项回归覆盖配置缺失、占位值、无效登录地址、权限过宽、符号链接逃逸、准备失败、账号不匹配、计划结构、接口无浏览器步骤、固定预期、敏感值替换、重复清理、延迟删除、删除期间归属变化、未知资源找回及中断的 UI 创建项目。

## 发现的问题与处理

| 首次发现 | 处理与验证 |
| --- | --- |
| 公开 Issue 的评论 REST 接口仍返回 401 | 核对官方 Notes 认证实现，改为明确的匿名权限边界用例；评论正文由 UI 刷新读取，独立 Issue GET 核对评论数量 |
| Agent 只填写正文第一行 | 原严格正文断言正确 FAIL；明确完整多行输入及 Markdown 编辑方式，新数据复测精确正文通过 |
| 失败后 Agent 尝试修复旧动作，清理超时并隔离 | 保留错误与超时，原生关闭确认后释放；用例声明明确收尾步骤，失败后继续下一实例 |
| 旧列表入口与当前 Work items 路径不同 | 修正列表与新建入口及取消后的冻结路径，单独复测通过 |
| 新项目描述没有保存 | 将创建项目与在 Settings / General 保存描述拆成两个动作，独立 GET 检查通过 |
| 预览采集了编辑器工具栏及隐藏菜单 | 保持精确正文预期，明确只采集预览中的粗体正文，新数据复测通过 |
| 延迟删除改名为原路径-deletion_scheduled-ID | 重新核对账号、命名空间、标记、精确后缀和 ID，使用实际 full_path 清理；原生认证查询确认 404 |

早期运行中的 FAIL、ERROR、BLOCKED、隔离和脚本检查失败记录均保留，未覆写为成功。

## 数据规模与边界

一次约 18 分钟的 17 场景混合运行产生约 1.54 GB 事件日志和 324 MB HTML 报告。整文件读入 Node 字符串的验证脚本触发了大小限制，后续改用流式检查；这属于验收读取方式的修正。事件快照和报告体积尚未在本次任务优化，先按单场景调试便于定位；完整集合仍可生成和执行。

当前未覆盖认证 GET 头、POST/PUT/DELETE 可信测试步骤、仓库推送、流水线、合并请求或角色权限矩阵。UI 场景采用当前 GitLab 页面，通过运行时定位采集；工具成功和业务持久化分别判断。
