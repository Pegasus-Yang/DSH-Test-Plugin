# 执行进度与实时预览验收

日期：2026-10-04。版本：0.7.0（开发版本）。依据：[实施方案](../design/执行进度与实时预览实施方案.md)。本轮完成步骤图、实际耗时、按会话隔离的进度入口，以及仅在当前页面 CDP 和有效首帧可用时启用的 Browscreen 原生浮窗。

## 实现范围

- 同一安装包包含 Host 与 Client；未修改 DSH 核心或 Browscreen 源码，测试仍由当前 Agent 的原生对话执行。
- 输入区上方展示步骤图，标题旁提供常驻“测试进度”入口，原生审核接管输入区时仍可查看详情。
- 状态来自已校验计划和实例记录，检查点失败不会因动作成功而显示通过；准备和清理单列，墙钟耗时包含等待。
- 专用 MCP 的 CommonJS 初始化扩展交付带运行/实例身份的页面级 CDP；保持 MCP 原有浏览器所有权和上下文清理。
- 当前浏览器目标可达、唯一页面和有效新 PNG 均满足后才返回 ready。API、无 CDP、不可达、无首帧和多标签不创建空画面窗口。
- 同源认证 iframe 显示 PNG，保留帧编号与采集时间；用户关闭后不反复弹出，结束后撤销画面、关闭浮窗并释放自己启动的 Browscreen。

## 验证中的调整与边界

MCP 的 ESM 初始化加载触发 `.esm.preflight` 限制，交付改为 CommonJS。公开 Browser.getBrowserCommandLine 需要 --enable-automation，配置仅用于启用预览的专用 MCP，不扫描系统浏览器或读取私有 Playwright 字段。

网页脚本最初切换会话后立即提交，任务落在上一会话而当前页面停留在空会话；按新会话 DOM 身份稳定后提交修正。插件未给另一会话打开画面，符合隔离规则。DSH 会复用已有空会话，验收等待条件也兼容这一行为。

直接 `/test` 的自然语言验收出现通报格式校验重试，并有一轮步骤超时；最终画面验收使用 `/test-plan`。本轮没有放宽原文通报或冻结预期规则，这些历史运行保留在忽略的运行目录中，不算本轮画面验证通过。

首版不支持多标签自动跟随、鼠标轨迹、PlantUML 渲染或 App 执行适配器。手动关闭/重开由客户端只读布局契约检查覆盖；真实网页验证覆盖自动打开、连续画面和结束关闭，未另跑手动关闭的模型联调。未修改用户现有 DSH profile；发行包可按[安装说明](../deployment/安装与运维.md)升级并配置可选预览。
