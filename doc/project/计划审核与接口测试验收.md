## 实现与验证范围

- `/test-plan` 在发起的同一 DSH 会话中进入原生 plan 模式，通过原生审核卡片要求修改或同意执行；未批准不展开执行实例、不得调用外部工具。
- `/test` 保留规划校验后直接执行；`/test-run` 保留直接执行 JSON 集合。
- 新增 `examples/httpbin-get.json`：一次 GET，完整 `{status, body}` 对象观察，3 条嵌套字段断言。API 请求只由 `test_capture` 的原生子调用发送，采集、断言、记录和报告复用同一链路。
- 构建通过；7 个测试文件共 71 项测试通过。覆盖草案替换、旧审核内容拒绝、要求修改、取消、等待超时、普通入口不审核、接口 PASS/FAIL、原始响应和账本重建一致。

## 真实宿主与独立环境

本地 DeepSeek Harness `0.2.1-alpha.1`，通过官方 plugin CLI 安装打包插件到 `.local/dsh-home` 的 web profile，在 13379 端口运行；沿用现有 MiniMax-M3.1 模型配置。浏览器操作使用独立 Chrome 窗口。未更新或重启用户 3080 服务。

发现 Web 标准预设将 planMode 放在隔离组，不能从全局或 Agent 根 Context 直接获取。最终使用官方 `commands.find/execute` 解析 `/plan`，原生 `exit_plan_mode` 处理审核；没有写入自定义宿主事件或修改宿主源码。
