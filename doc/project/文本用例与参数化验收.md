## 原生审核与报告复核

CSV + Markdown 首次待审时实例数 0、证据数 0、HTTP 调用数 0；审核页显示两个列名、两行所有参数、两条原始用例及四个实例的展开任务。通过“要求修改”将每实例改为“发送请求、核对同一响应”两步；程序比对两个草案的完整输入快照完全相同，第二版所有实例均两步。批准事件序号 56，首次 HTTP 派发序号 95，严格晚于批准。

四实例回显依次为 keyword=agent、keyword=testing、client=dsh、client=web，状态码均为数字 200。每个实例恰好一次 HTTP 请求，没有 Playwright 调用；断言分别复用各自响应。CSV 直接任务的批准序号 27、首次执行序号 39；浏览器文件用例同样是批准序号 27、首次执行序号 39。

真实 Chrome 从最终回复链接打开四实例报告；按源用例 case_2 筛选剩 2/4，再按 row_2 筛选剩 1/4。展开“用例来源与参数”，原始 `${client}` 模板、参数 `testing/web` 和展开任务对应正确；断言页显示实际/预期 `200/200`、`web/web`。浏览器用例报告显示数字 `1 neq 0`，与记录及最终对话一致，布局正常。

五个成功批次共 11 个实例。各批次 `validate-report --data-only` 均通过，原始 plan.json 与 results.plan 相等，执行和清理会话均为发起会话。最终包的主要场景在 `6b23430` 验证；TXT 首次成功发生在其之前，其后只修正空参数通报及未审核取消的边界，TXT解析/执行接口未变。
