2026-10-17。实现及三版无豁免安装、公开 SDK、381 项回归、Web 配置和安装生命周期检查已经完成；**必要真实验收尚未全部完成，当前不是正式发版**。MiniMax 返回 HTTP 429／错误 2056，明确提示 Token Plan 用量达到上限，导致 alpha.1 的 GitLab UI 和 alpha.2 的后续真实场景中断。

## 实现范围

同一个 `dsh-test-plugin@0.13.0` 候选声明支持 DSH `0.2.1-alpha.1`、`0.2.1-alpha.2`、`0.2.1-alpha.3`。全部 22 个 DSH peer 使用三个精确版本的联合范围，optional 属性保留；开发／构建 SDK 继续固定 alpha.3。没有新增运行时版本分支。

`dsh-compatibility.json` 是支持集合和 CI 矩阵的共同来源；`compat:sync` 显式同步，构建与发行检查只校验。新增 18 项范围、开发基线及不完整包反例，完整回归为 318 项单元和 63 项集成，共 381 项。

真实回归发现通用接口数组指导缺失：既有 `.length` 指导原来仅在 RunBridge 分支提供。本次移入所有后端共用指导，补充 observation_ref／unit 的工具说明；数组值、冻结预期及严格比较规则保持不变。已有数组回归扩展为同一响应读取 iid=3、body.length=1、labels.length=0，确认只采集一次。

## 真实模型与业务结果

各版使用独立 home、profile、工作区、MCP、浏览器及输出。alpha.3 的完整脚本退出码为 0，整体 summary.status=PASS；alpha.1／alpha.2 的整体状态保持 FAIL，并另存不依赖模型的卸载成功证明，不用部分通过覆盖整轮失败。

alpha.1 的核心 Markdown UI／API、CSV、审核关闭／修改／重新批准／取消、普通聊天、同会话与新会话连续运行、慢接口在途停止均通过，GitLab 3 条接口的 21 个固定断言通过。GitLab UI 中出现服务端额度错误：SDK 连续 5 次重试仍为 RATE_LIMIT／429／2056，连收尾模型轮次也不可用，最终两实例 ERROR，资源保持隔离。

alpha.2 的本地 UI、API 正向与固定反例、普通聊天和同会话接口再运行通过；CSV 审核时连续 5 次相同额度错误。该版新候选的 CSV、审核取消、在途停止及 GitLab 场景没有完成，不能借用上一候选的成功记录补成当前通过。

alpha.3 的 6 类业务报告共 10 个实例符合固定预期：本地 UI 1、API 正向 1、固定反例 1、CSV 2、GitLab API 3、GitLab UI 2；另有审核取消和在途停止验证。GitLab UI 后以独立 GET 确认 closed／dsh-smoke 仍只有原 gamma，取消的草稿没有持久化。

各轮检查认证 HTML、账本重放、原始观察、冻结预期、证据 SHA、离线桌面／窄屏、筛选和附件，以及实际步骤、手工导出与最终记录的一致性。继续前检查实际 Agent 空闲、测试作用域关闭、在途工具归零。集成回归中的 Agent 生命周期替身另行覆盖未知隔离、重启恢复和释放约束，不表述为真实模型执行。

新候选还在独立 alpha.1 API-only profile 上复验了原 GitLab 失败：沿用原固定数据与预期，3 条／21 项全部通过，并确认 Agent 空闲。没有依靠浏览器或认证接口采集完成此项。

## 原失败与修正

- 驱动准备先后修正发布清单入口读取、文件符号链接扫描、隔离副本遗漏 examples／dist／发行测试夹具等问题，没有因此修改插件业务执行逻辑。
- 缺 SDK 反例最初选择只有类型导入的 dsh-agent，入口仍可加载；改为真实运行时依赖 dsh-llm 后，三版均准确拒绝缺包。
- 同机三版同时回归触发几项原测试的 5 秒框架时限。复验串行 SDK 阶段，保留测试默认时限及生产预算，不删除或跳过测试。
- 首轮 UI 三个断言通过，但步骤超时，驱动 15 秒收尾预算也不足，最终 ERROR 且隔离。该失败报告通过账本、证据、离线和窄屏检查；报告完整不等于业务通过。正式三版受控模型预算统一为步骤 600000 ms、收尾 180000 ms、取消宽限 500 ms，生产默认值保持不变。
- CSV 已得到固定 PASS／FAIL，离线校验器误把行实例 case_id 当作用例分组值；按报告实际 data-case 选择后，完整离线校验通过。普通聊天因模型省略句末句号被校验器误报；改为匹配同样内容和可选结束标点，不改业务结果。
- 前一候选 GitLab 接口三版均出现数组与数量比较的 FAIL。程序严格比较正确，缺少通用指导使模型误用 unit:length。共用指导和工具 Schema 修正后，新候选的原固定 21 项检查通过，旧失败不改判。
- 新候选 alpha.1／alpha.2 首次审核超时。原始宿主日志确认模型调用了 exit_plan_mode，但把草案中文引号改成英文引号，一致性守卫正确拒绝；尝试的 bash／read 也被规划守卫拒绝。分别用全新 profile 重跑，不放宽审核一致性。
- 临时目录首次误用本机损坏的 Homebrew Node 25.6.1；后续显式使用 Node 22.22.3。pnpm 11.7.0 使用任务内安装，不修改系统工具。
- 当前外部阻塞为明确 Token Plan 额度耗尽，已停止无效重试。alpha.1／alpha.2 分别保存 quota-failure.json，保留 SDK 的 5 次 RATE_LIMIT 事实。

## 收尾与交付边界

所有本轮宿主及夹具已停止。alpha.1／alpha.2 额外卸载后 Web／MCP 检查通过，补充启动的宿主确认 PID 不存活。GitLab 专用项目按三个原准备记录清理，并逐个登录 GET 核对 404；本机输入、原始运行和隔离标记保留。

本轮保存中文本地开发提交，不创建正式 v0.13.0 标签，不推送。项目约定要求必要验收完成后才创建附注标签，当前尚未满足。GitHub Actions 新矩阵实际运行、远端标签目标和固定 Git 标签安装，须在用户审核并手动推送后核对。本机执行不冒充远端绿色结果；本轮不新增 RunBridge 实机、Browscreen 录像或其他操作系统真实模型验收声明。

## 恢复后的必要工作

1. 指定本机已配置且有额度的模型，或恢复原 MiniMax 额度；不自动购买或升级套餐。
2. 重新准备 alpha.1／alpha.2 各自的 GitLab 专用数据，继续使用当前种子和模板，不根据响应改写预期。
3. alpha.1 补齐 GitLab UI 和最终数据核对；alpha.2 补齐 CSV、取消、在途停止及 GitLab 接口／UI。保留中断记录、新的真实证据和产物对应关系。
4. 复核全部发布门禁，归档最终日期和版本状态，完成本地发布提交及附注标签；由用户审核后手动推送。
