## 兼容问题与修复

新宿主中，用户在原生计划审核选择“要求修改”时，`exit_plan_mode` 正常返回 `{ approved: false }`，调用 `concludeTurn()`，保留 plan 模式等待用户反馈。旧插件只用 `result.isError` 判断审核是否关闭，因此会把这个正常结果当作还需催促审核的状态，在轮次结束前再次 steer 模型。

插件改为只在当前审核明确返回 `approved: true` 时批准并冻结草案；其余审核结果均停止催促，继续等待用户。重新提交草案会恢复正常审核；原有要求修改、取消、停止和同草案校验继续沿用。

回归先复现新分支失败：关闭审核后出现一次不应发生的 steer。修复后同时验证异常拒绝和正常 `approved: false` 两种结果：没有冻结计划或业务实例、轮次结束后仍可等待、重新提交并批准后才进入执行。
