# 手工用例调整验收

日期：2026-10-06，Asia/Shanghai。基线为 v0.11.0，调整作为 0.11.1 修复版本交付；只创建本地提交与附注标签，不推送，旧标签保留。

## 用户要求与实现

| 要求 | 当前实现 |
| --- | --- |
| 执行数据和地址不脱敏 | 派发前单独保存 manual-source.json，导出的手工操作保留真实值；运行审计继续按原规则脱敏 |
| 只保留五部分 | 用例名称、原始用例、前置用例、实际步骤、收尾；不输出运行编号、状态、实际值、证据、耗时或参数快照 |
| 只用最原始描述 | 自然语言用初始原文，文字文件/CSV 用原始条目或模板；JSON 无独立 planning.original_task 时留空，已获用户确认 |
| 三列且操作合并数据 | 每阶段独立编号，只有序号、操作、预期；访问、输入、填表、按键等真实值写在操作中，无独立预期留空 |
| 避免 HTML 实体 | 移除原 Markdown 的字符实体编码，保留下划线等普通字符，仅使用必要的 Markdown 转义 |

手工模板面向下一次执行：只采用已确认成功的动作，失败、未知或未派发尝试仍由运行报告及实际步骤 JSON 保留；已执行的业务检查保留其原冻结预期，不把本轮 FAIL 改为 PASS。用户声明的前置和收尾按原顺序保留，缺失的业务动作不补造。

## 数据与下载

- 手工原始资料与 Markdown 为独立 600 权限文件，存放在本机运行目录，不提交 Git；内容未变时不重复写原始资料。
- 运行报告仅放手工 Markdown 下载链接，未脱敏正文不内嵌 HTML；JSON 下载继续是脱敏的实际运行记录，不作为手工执行模板。
- 批次及单例使用 manual-cases.md、manual-cases-1.md 等文件；原始资料不进入 HTTP 白名单。
- 认证报告对准确手工 Markdown 路径签发 GET/HEAD 票据，不能更换其他实例、重建文件、JSON 或写请求；离线须保留对应独立文件。
- 重建只读原账本及手工资料，生成 -rebuilt 文件，原件与业务结果不改写。0.11.0 及更早缺原始资料的记录，无法恢复已经脱敏的值。
