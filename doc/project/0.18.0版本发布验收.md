# 0.18.0 版本发布验收

状态：2026-10-31 验收通过，按项目约定仅本地提交与附注标签交付，不推送。基线为 0.17.0，实施依据为用户已批准的[通用工具运行方案](../design/通用工具运行方案.md)。

## 交付范围

- 动态发现当前 Agent 的业务工具，取消固定浏览器后端准入；保持自定义服务原有名称和参数。
- 支持通用结构化及文本结果提取，保留程序断言、固定预期、原始响应证据和提取定义；同一次动作返回可直接生成观察。
- 默认外部上下文管理；可选本轮资源合同按原身份关闭，未知状态隔离，原连接和定义不一致时拒绝恢复。
- 媒体能力独立检测，统一操作记录、手工 Markdown 及报告，并兼容原有连接和旧计划。

## 预验收整改与边界

1. 实际手工导出暴露地址重复和 CSS 参数混入正文，已修复并增加回归。
2. 真实 RunBridge 暴露目录遗漏 Agent 内工具的问题。目录、定义校验及恢复现均使用同一 Agent 视图；作用域专项和真实 RunBridge 复验通过。
3. 部分预验收由模型选错提取路径触发 ERROR。规则锁定后未改写观察或业务预期，原会话仍按身份关闭；测试服务随后补齐真实返回格式说明。该记录体现通用工具对说明质量的依赖，不计为正向通过。
4. 初轮设置脚本在保存后立即读取，尚未等到运行配置更新；改为有界等待实际回读。一次并行重 IO 回归触及测试的 5 秒预算；最终完整回归使用单工作进程，多宿主共享 SDK 回归串行锁，不更改生产超时。
5. rc.2 首轮隔离负例发现临时验证器依赖链接使“缺少 SDK”目录继承了项目 SDK，门禁按预期拒绝该轮验收。移除该链接后，在新目录完整复验通过；该次失败保留为验证环境问题，不删除记录或放宽门禁。
6. rc.3、rc.5 首轮真实模型分别对对象使用字符串 `contains`、对元素计数使用不完整的 `range`，程序记录 ERROR。保留这两轮，使用相同候选包、相同业务种子与验证脚本，在新的 profile 和专用项目完整复验通过；不修改比较器或把 ERROR 当成预期 FAIL。

早期候选与中止的 SDK 准备保留为预验收记录，不计入最终同包矩阵。基本工具运行不保证任意服务具备截图、CDP、录像或资源查询能力，也不能仅凭工具名称证明服务内部动作的业务含义；明确要求但缺失的能力仍不能形成整体 PASS。

本机运行资料保存于忽略目录 `artifacts/generic-0.18.0/`；模型配置、认证 URL、真实账号、原始输入、视频与下载不提交。远端推送、GitHub Actions 和 Release 发布不属于本轮自动执行范围。
