# 0.13.1版本发布验收

[文档导航](../README.md) · [版本发布](../deployment/版本发布与Git标签.md) · [多版本验证](../deployment/DSH多版本验证.md) · [0.13.0 业务基线](0.13.0多版本兼容验收.md)

2026-10-18。本次将 `0.13.0` 后的 CI 修正归入补丁版本 **0.13.1**，同步包版本、新运行的 `manifest.plugin_version`、中英文当前文档、安装命令和构建产物。创建中文本地提交和附注标签 `v0.13.1`，由用户手动推送；已发布的 `v0.13.0` 保持原状。

## 变化与支持范围

- CI 浏览器操作通过原生按钮完成已知首次引导，设置入口可操作后才继续；未选择工作区时也能验证设置、停用与卸载。引导切换时短等待后重新识别当前弹窗；未知弹窗仍失败，新增分支使浏览器专项合计 8 项。两次远端失败、复现和 0.13.0 原包的 Linux 补验见 [CI 首次引导回归验收](CI首次引导回归验收.md)。
- 工作流 Action 固定到已核对的 Node.js 24 稳定版本，所有作业使用 `ubuntu-24.04`；项目脚本继续使用 Node.js 22.22.3、pnpm 11.7.0。Action 内部运行时与项目 Node.js 分别维护，详见[运行环境](../deployment/DSH多版本验证.md#ci-运行环境)。
- 同一个包继续支持 DSH **0.2.1-alpha.1、0.2.1-alpha.2、0.2.1-alpha.3**，构建 SDK 固定 alpha.3，22 个 DSH peer 和单一兼容策略不变。运行记录版本随包更新，集成回归从 `package.json` 读取预期，避免后续发布遗漏硬编码。

## 验证范围

新版仅调整发行版本及 CI，测试业务逻辑、用户用例和外部接口保持原状。本次验证重建入口、版本记录、发行包、8 项浏览器专项，以及同一候选包的三版确定性完整矩阵。受控真实模型和 GitLab Markdown UI／接口业务证据沿用 [0.13.0 已完成记录](0.13.0多版本兼容验收.md)，通过运行文件等价核对说明复用依据；原始记录仍保留版本 0.13.0，不改写为本版重新执行。

运行产物只构建一次。第一份打包草稿在发布自审时发现 changelog 仍有上一轮“版本保持不变”的措辞，在宿主 SDK 安装阶段终止验证；修正后的第二份包完成 alpha.1、alpha.3，alpha.2 在欢迎页被凭据弹窗替换后仍等待旧按钮而失败。新增真实 Chromium 场景先复现相同超时，再将已知弹窗点击纳入短等待重试；macOS 与 Linux 的 8 项专项均通过。修复脚本并同步当前文档后，统一使用上述最终摘要重新建立三个宿主；前两份包、失败与中止记录保留，不作为最终验收。

重新核对 0.13.0 的三份业务汇总，每版含 5 类核心／接口场景、2 个 GitLab Markdown UI 场景及实际 Agent 空闲、测试作用域关闭、在途工具归零与持久化证明。固定反例的 FAIL、CSV 的 PASS／FAIL 都是原定业务预期；前序整轮失败及后续分项补验仍保留原貌。本版以严格运行文件等价为复用依据，不宣称使用 0.13.1 重新调用了模型或 GitLab。

## 验证环境与证据

本机矩阵使用 Docker `linux/amd64` 容器（macOS 上通过 Rosetta 运行），系统为 Debian Bookworm，Node.js 22.22.3 / pnpm 11.7.0。宿主和插件通过公开安装包建立独立 profile，三个受约束的 SDK 来自各自官方发布标签；没有使用本机宿主链接。浏览器为实际 Chromium，确定性矩阵不配置模型凭据。此结果是本地 Linux 复验，固定 `ubuntu-24.04` 的远端 GitHub Actions 和固定 Git 标签安装须在用户推送后确认。

原始证据保存在忽略目录 `artifacts/validation/dsh-0.13.1-release/`；入口为 `summary.json`，包括同包摘要、源码摘要、各宿主结果、失败与成功的浏览器回归、业务证据复用依据及清理记录。认证 URL、密钥、实际用户 profile 和完整宿主日志不入 Git。本轮 18 次宿主启动均确认停止，随后移除本次专用临时容器。
