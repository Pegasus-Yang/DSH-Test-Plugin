# 详细实施方案

## 1. 实施原则与前置条件

以一个可安装原生 TS 插件逐步完成 R1–R5，先打通最小真实链路，再扩大覆盖。当前只编写方案，以下全部为待执行任务。阶段通过以 [阶段校验清单](阶段校验清单.md) 和证据为准，不以代码已写完为准。

需准备：可写的插件工程、隔离 DSH home/profile、一个模型路由、可重复重置的本地测试应用、测试账号、浏览器和 API 接入工具。前期示例必须使用测试数据，不拿生产业务验证写操作。具体浏览器/API MCP、模型、发布版和操作系统在 M0 记录，不预先假定任意现成工具都能满足观察和取消合同。

## 2. 拟建工程

以下文件在后续开发阶段创建；本次方案目录没有这些产品代码。

```text

  src/

    host.ts                       DSH公开接口适配

    planner.ts                    规划与规则来源

    recorder.ts                   调用归属、事件写入、证据
    assertions.ts                 比较器
    adapters/browser.ts           已选浏览器工具结果适配
    adapters/api.ts               已选API工具结果适配

  skills/testing/SKILL.md          测试方法，不存秘密
  templates/report.html           固定报告模板

  tests/integration/              假工具与DSH边界测试
```

依赖选择：复用锁定版本 DSH 的 peer API、既有 Schema 库和测试约定；TS 单元/集成测试优先 Vitest。工具链以 M0 实际插件示例和发布构建方式为准。拟设置 `build`、`typecheck`、`test:unit`、`test:integration`、`test:e2e` 脚本，后续以 `pnpm run <script>` 执行；这些脚本当前不存在，不是本次已运行的命令。

## 3. 阶段总览

| 阶段 | 目标 | 前置 | 出口交付 |
| --- | --- | --- | --- |
| M0 | 验证宿主扩展和工具兼容性 | 环境与测试账号 | 可安装空插件、兼容性记录、零核心补丁的最小工具闭环 |
| M1 | 固定数据、状态和记录合同 | M0基本装配可用 | Schema、展开/聚合函数、事件写入、负向测试 |
| M2 | 自然语言生成有效计划 | M1 | 规划Skill、结构化提交工具、缺口处理、知识引用 |
| M3 | 单实例执行与断言 | M0–M2 | Web/API实际闭环、原生审批/取消、证据与断言 |
| M4 | 多实例与数据隔离 | M3 | 串行批次、实例展开、清理、错误继续策略 |
| M5 | HTML报告与不完整结果展示 | M1、M4 | 离线HTML、筛选/展开、准确统计、可重建报告 |
| M6 | 打包、重复验证和交付 | M0–M5 | 干净环境安装、故障回归、使用说明与完整证据包 |

M5 模板可用 M1 固定样例提前制作，但不得替代真实结果验收。M0 接缝不成立时允许继续独立的合同/模板工作，不应继续堆砌依赖失败接口的 runner。

## 4. M0 宿主与工具兼容性

**输入：** 上游参考记录、候选发布包、一个浏览器接入和一个 API 接入。

1. 锁定上游提交/包版本、Node/包管理器版本、操作系统和模型路由，创建独立 DSH home/profile。确认实际安装产物与源码证据的差异。
2. 按同版本官方插件样例创建最小包，验证本地安装、加载、卸载和重新加载；注册 `/test-status` 验证命令入口，不直接开发完整 UI。
3. 创建独立运行 Agent，装配一个假工具，验证 followup、事件接收、idle、dispose；确认不会递归调用自己或等候自己。
4. 核对并实际运行 `pre-execute / guard / tools/result / concludeTurn`，覆盖进入管线前取消、参数物化失败、PTC 直接调用拒绝及同批工具；锁定能在管线前捕获模型调用身份的公开入口，证明结果不靠当前步骤补绑。决定 native/PTC 模式及限制；捕获入口不可用则阻断 runner 开发并复审。
5. 接入两个真实工具，记录工具名、Schema、返回样本、附件、取消支持、上下文标识和版本；验证能预先指定采集调用并唯一绑定输出槽，取得可信响应。测试忽略取消的假工具，确认宿主等待与插件收尾期限的边界。
6. 在独立运行会话触发无害审批，确认用户能看到并作答、拒绝时工具体不执行；不能只验证函数返回。
7. 核对插件分发许可与依赖声明，把无法获得原始响应/隔离上下文等缺口登记为已知限制。

**输出：** 兼容矩阵、最小插件包、假工具日志、真实返回样本、审批界面/结果证据。**出口：** C00–C07 全部通过；关键接口需要核心补丁时记录证据并重新评审插件方案，不悄悄 fork。

## 5. M1 数据与记录合同

1. 将 [数据合同](数据契约与状态规则.md) 实现为运行时 Schema 与 TS 类型，准备/业务/清理复用 Step，资源及清理条件显式绑定；给出合法/非法 fixtures。
2. 实现 case/data 展开、变量绑定、依赖校验和聚合纯函数；拒绝必需步骤依赖可选步骤/输出，按唯一判定表测试。实现不可变输出槽和操作数快照，用旧上下文、多次采集、重复/迟到事件做反例。
3. 实现单 writer、唯一批次目录、事件顺序、身份固定和结果快照。将工具映射与 writer 分离，便于模拟迟到结果/写入失败。
4. 实现证据受限路径、内容摘要、脱敏、附件原子发布；manifest 保存版本和秘密引用。
5. 定义断点后的只读重建：有效尾部中断可生成不完整报告输入，异常中间记录必须报错；保存实例修订应用记录和隔离事实，不能重建时套用最新修订/观察。

**输出：** 合同与 recorder 单元测试、示例计划/事件/结果、错误诊断。**出口：** C10–C17 全部通过，聚合结果不受事件到达顺序污染。

## 6. M2 规划与检查点

1. 注册 `/test` 与 `/test-run`，按需接受受支持附件；所有输入统一转换为任务来源引用。
2. 建立只读规划 Agent，装配测试 Skill、项目规则读取与 `test_submit_plan`。明确只能输出建议，不能自定通过结果。
3. 校验模型提交，缺字段最多有限次纠正；预算用有界配置表达并记录实际值。缺预期/冲突必须形成用户可读问题。
4. 实现计划快照和规则版本引用，对已明确用例直接进入执行，不额外增加无条件确认。
5. 实现 `test_propose_checkpoint` 验证：新增步骤显式 required、冻结适用实例和插入边界、验证来源/权限/依赖/去重/预算。实现 plan_revised 与 revision_applied 提交及实例有效必需集合；标注事后检查，验证必需新增断言可以改变适用实例结果但不改已终结实例。
6. 用固定描述评估步骤/数据展开，并测试网页或知识内容诱导“忽略断言”的情况，确认被测内容不能覆盖控制规则。

**输出：** 规划Skill、输入到计划样例、缺口问答记录、计划修订案例。**出口：** C20–C27 全部通过；模型输出不能越过 Schema 和规则校验。

## 7. M3 单实例执行、断言和控制

1. runner 创建实例专属 Agent/session，并通过受信 mapping 绑定当前步骤、预算和允许目标；显式选择工具能力。
2. 在测试应用上完成打开页面、填写、点击、读取 API/页面结果；工具返回由 adapter 生成 Observation/Evidence。
3. 使用 M0 已验证入口实现管线前绑定和结束归档；早退、拒绝、参数错误、抛错、超时和取消均有归属。未结算调用保留 unknown，不伪造结束；输出槽绑定持久化后才采集。
4. 实现 `test_finish_step` 与业务在途清点：控制调用不等待自身；终结前等待必需输出和 writer，下一步前等待控制调用结束及 idle。模型提前 idle 有界修复，仍缺 finish 记 ERROR；同批后续动作和迟到结果不能突破终结准入。
5. 实现确定性比较器。设置“UI 看似成功但 API 业务字段错误”的故障，确保工具成功与断言失败并存。
6. 复用在线审批，记录执行/审批/收尾/清理预算；停止业务准入并有界取消。忽略取消且不返回时仍封存 ERROR、不完整结果及持久隔离标记，禁止后续批次；迟到结果仅作审计。
7. 加入四个 hook，按合同区分 before_step 拒绝/错误、可选步骤局部错误、后置 hook 警示与完整性错误；不可覆写历史断言。
8. 在途全部结算后以独立清理 Agent 的 open turn、新信号执行适用预授权清理，验证该会话的原生审批可达。准备部分失败仍定位已创建资源，资源未知不当作不适用；收尾超限不清理、不声称资源已释放，清理挂起同样隔离。修订入口与实例终结按单 writer 排序，fail-fast/取消拒绝未提交修订。

**输出：** 至少一个真实 Web+API实例、原始证据、注入故障结果、拒绝/停止日志。**出口：** C30–C37 全部通过，不能仅用假工具替代本阶段真实宿主验收。

## 8. M4 批次与隔离

1. 从冻结计划展开 CaseRun，先支持一个 case 三行数据，再支持两个 case 各自数据；拒绝隐式组合。
2. 一次只允许一个批次活动；重复启动返回现有批次信息或明确 busy，不误创建并行运行。
3. 每个实例创建/释放会话，工具层选择对应浏览器上下文；无法隔离的工具使用串行重置，并把限制写入说明。
4. 仅必需业务失败/未决触发 fail-fast，可选局部失败只警示；独立实例继续，共享前提损坏阻断依赖实例，隔离时全部剩余实例阻断。
5. 用户取消后未开始实例记 CANCELLED，活动实例有界收尾；超限封存 ERROR 并保留未结算调用，统计包含全部实例且不重复计入 cancelling 与终态。
6. 清理数据以 fixture/实例标识定位，不影响其他用例。首版不自动重试有副作用操作。

**输出：** 三行数据批次、多 case 批次、独立性与失败继续记录。**出口：** C40–C47 全部通过，每个输入数据行都可追溯到唯一实例。

## 9. M5 报告

1. 用统一 results 投影模板：总览、用例/数据筛选、失败筛选、步骤展开、预期/实际、来源和证据。
2. 根据终态与在途状态统计实例，显示结果结算率及不完整/隔离标记；不把结果封存当作外部执行结束，不将尝试、工具次数当成用例数。
3. 对失败、错误、审批拒绝、取消、缺证据和清理异常分别设计展示，避免一律显示为“失败”。
4. 无 CDN 离线打开，附件使用相对链接；转义不可信字段，验证 `<script>` 之类内容只按文本展示。
5. 以真实 M3/M4 结果验证，测试报告目录整体复制后的链接。截图/trace 大附件不强行全部内嵌。
6. `/test-report` 按实例修订应用记录、操作数快照只读重建；缺少记录则标不完整，迟到结果单列不改判，模型/工具调用数不增加。

**输出：** 完整和不完整报告样例、浏览器截图与交互校验记录。**出口：** C50–C57 全部通过。

## 10. M6 打包与交付

1. 在干净 DSH home/profile 安装打包产物，按文档配置模型和工具；确认没有依赖开发目录的绝对路径。
2. 完成 typecheck、构建、单元与集成检查；真实 e2e 单独标明模型/工具环境、费用和结果，不把跳过写成通过。
3. 将验收集至少完整重复三轮：每轮保留 manifest、计划、日志、结果、报告和附件；不只保留最好一轮。
4. 校验安装、卸载、重载和取消后的资源收尾；永不返回的工具须如实隔离，不宣称资源全部释放。异常退出后标记不完整并恢复隔离门禁，不能继续未知副作用。
5. 整理配置、命令、数据格式、工具版本及故障排查；给出隔离解除操作：核实外部执行停止、重置环境、保存处置证据并解除门禁，不能仅重启/删记录绕过。实现该运维流程后才完成 M6。
6. 汇总清单，通过项附证据，失败/阻塞项进入问题表；涉及门禁、假阳性、数据串扰的问题解决前不宣称首版可用。

**输出：** 可安装插件、源码/锁文件、使用文档、完整证据和验收结论。**出口：** C60–C67 全部通过，或明确列出用户接受的非关键限制及范围调整；不自动将未测项划为不适用。

## 11. 测试应用与固定验收数据

fixture 应包含登录页/接口、订单试算页/接口、可查询的写操作计数器、可注入延迟/错误/缺字段开关。控制故障开关属于验收程序，不向被评估 Agent 暴露正确答案或切换权限。

| 场景 | 数据/故障 | 独立预期 |
| --- | --- | --- |
| F01 正常登录 | 有效凭据 | 确定性断言 PASS |
| F02 无效凭据 | 错误密码 | 正确拒绝登录也应 PASS，而非把 HTTP 错误码一律当测试失败 |
| F03 业务错误 | 独立预期18000；UI实际18000、API实际19000 | UI金额 PASS，API金额与UI/API一致性断言 FAIL；分别运行各断言子场景避免 fail-fast 遮蔽，实例 FAIL |
| F04a 必要输出缺失 | 必需动作要求 auth_result，工具仅返回“成功” | 动作 ERROR、依赖断言 SKIPPED、实例 ERROR |
| F04b 工具错误 | 必需工具分别返回 isError、损坏协议、超过执行期限后结算 | 动作 ERROR、依赖断言 SKIPPED、实例 ERROR |
| F04c 比较器错误 | 必需比较器注入执行异常 | 断言 ERROR、实例 ERROR |
| F05 审批拒绝 | 要求审批的测试提交 | 提交计数 0，实例 BLOCKED |
| F06a 正常取消 | 延迟工具在收尾期限内结算，适用清理成功 | 新业务动作数不增加，清理仅在结算后执行；实例 CANCELLED |
| F06b 收尾超限 | 工具忽略取消且始终不返回 | 有界输出 ERROR、不完整/隔离；清理调用数0，未开始实例 CANCELLED，新批次拒绝 |
| F06c 清理失败 | 业务已取消且结算，必要清理返回错误或挂起 | 实例 ERROR；挂起另标不完整/隔离，禁止新批次 |
| F07 证据不足 | 动作确认输出满足必要条件；已声明的可选业务输出缺失 | 动作 SUCCEEDED、必需断言 INCONCLUSIVE、实例 INCONCLUSIVE |
| F08 批量与隔离 | 三行凭据、两个case、脏登录态 | 实例数/绑定正确，无前例污染 |
| F09 中断与写盘错误 | 进程中断、拒写目录 | 不完整/ERROR，不能生成虚假完整报告 |
| F10a 必需修订 | 实例A已终结；有来源规则向B/C追加必需断言，B观察不符、C符合 | A结果不变，B FAIL、C PASS；各自有效集合与报告重建一致 |
| F10b 非法修订 | 无来源猜测、目标含已终结实例、插入点已过 | 拒绝生效；无来源项可转为澄清草稿，不产生执行步骤 |
| F10c 可选检查 | 可选断言 FAIL/局部采集 ERROR；后续必需断言 PASS | 可选问题警示、后续继续，必要清理成功时实例 PASS |

F01–F10 表示场景族，三轮验收必须覆盖表中全部字母子项。F03 以独立子场景分别验证两个 FAIL，不能要求 fail-fast 后仍执行所有断言。准备、清理和运行完整性故障另按 C10/C12/C35–C37 的反例执行。

工时在 M0 完成后按实际工具适配缺口拆解。旧调研 75–110 人日属于更完整产品 MVP，不直接作为本次纯插件验证版排期。
