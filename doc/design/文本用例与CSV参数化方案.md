# 文本用例与 CSV 参数化方案

日期：2026-10-04。状态：用户已同意总体方案，按本文推进实施。目标版本：0.6.0。

## 目标

用户用普通文字描述测试，不必填写内部 JSON 执行契约。文件边界、参数读取、实例数量和替换由程序确定；模型只负责理解每个具体任务、拆解业务步骤及执行时选择操作。继续使用发起会话的原生模型循环、plan 审核、工具管线和报告。

## 用户入口

| 命令 | 输入与行为 |
| --- | --- |
| `/test <任务>` | 保留单条自然语言任务，通报后直接执行 |
| `/test-plan <任务>` | 保留单条任务的原生审核 |
| `/test-run cases.txt` | 非空行分别作为用例，规划通报后串行执行 |
| `/test-run cases.md` | 最外层列表项分别作为用例，规划通报后串行执行 |
| `/test-plan --file cases.md` | 读取 TXT/Markdown 用例，统一审核后执行 |
| `/test-data data.csv <任务模板>` | 参数化任务，始终先进入原生 plan 审核 |
| `/test-data data.csv --file cases.md` | 文件用例与 CSV 组合，始终先审核 |
| `/test-run suite.json` | 保留完整 JSON 集合兼容入口 |

文件路径相对于配置的 workspace，保留现有工作区边界。含空格的路径可用单双引号包裹；模板中的 `${参数名}` 是 DSH 对话文字，不由 shell 执行。

## 文件语义

### TXT

UTF-8 文本，每个非空行是一条用例；忽略纯空白行，保留原始行号。兼容 BOM、LF 和 CRLF。用例至少有一条明确检查点，缺失时沿用原生追问，不默默生成通过预期。

### Markdown

使用 Markdown 语法树识别根节点下的有序或无序列表，每个直接列表项是一条用例。项内的段落、嵌套列表、表格及代码块整体保留，不继续拆成额外用例。支持多段顶层列表，按文档顺序编号。列表之外的文档说明作为共享背景保留、展示并传给规划，不额外生成用例。只有嵌套或代码块中的列表、没有顶层用例时明确提示。

示例：

````markdown
# 查询接口

- 验证查询参数回显

  请求 https://httpbin.org/get，使用下面的查询参数：

  ```json
  {"keyword": "${keyword}", "client": "${client}"}
  ```

  验证状态码为200，返回参数与请求相同。

- 请求 https://httpbin.org/user-agent，验证返回非空的 user-agent。
````

### CSV 与替换

首行是参数名，后续每条 CSV 数据记录是一组参数。使用标准 CSV 解析，支持引号、逗号、字段内换行和 BOM。字段值保留字符串形式，包括前导零、空字符串及空格。空白物理行忽略，合法的空字段记录仍保留；空/重复表头、列数不一致、没有数据、模板引用不存在的参数给出明确错误。

每条原始用例使用全部 CSV 数据行，采用用例优先、数据行次序：3 条用例 × 2 行数据 = 6 个实例。单任务模板视为一条原始用例。额外 CSV 列保留并展示，不要求模板使用全部列。

`${参数名}` 只替换一次，不执行表达式，也不递归替换参数值中的占位文本。替换发生在用例边界识别后，参数中的列表符号或换行不能增加用例数量。参数先进入任务描述；URL 编码、HTTP 参数、DOM 定位和比较器仍在执行步骤中由模型按实际情况处理。

## 规划与审核

程序读取并保存输入快照，生成稳定的来源用例和数据行标识，再展开具体任务。模型为每个展开任务提交名称、简短思路、业务短句与文字检查点；校验实例标识完整且唯一，禁止遗漏、合并或添加未导入的实例。

参数化与文件审核入口使用原生 `/plan`、`exit_plan_mode`，完整审核内容包括：

1. 原始命令/任务、用例文件及 CSV 来源。
2. 原始用例模板、共享说明、参数名与 CSV 数据行。
3. 原始用例数、数据行数、执行实例总数。
4. 每个实例的来源用例、数据行、所有参数值和替换后的完整任务。
5. 各实例的拆分思路、业务步骤与检查点。

参数值用明确的字符串表示区分 `"001"`、`""` 和换行，不因 Markdown 表格语法隐藏数据。模型不能自行生成或修改参数预览。要求修改时替换文字草案并重新审核；只有当前完整草案获得原生批准才执行。读取后不自动跟随文件变化：修改用例文件或 CSV 后取消当前草案并重新提交，避免审核内容与实际数据不一致。

非审核 TXT/Markdown 入口也先完整通报用例及步骤，再执行。单条 `/test` 行为保持不变。规划阶段不请求目标或提前运行操作。

## 内部实现与记录

新增职责单一的文件解析模块，输出文本输入快照；多实例文字计划沿用现有 intent 步骤。每个展开任务作为内部独立 case，数据标识记录 CSV 行，避免共享步骤被运行时修改或用参数字符串替换断言结构。报告额外显示来源用例编号、数据行、参数和展开任务；内部 case_id 不要求用户填写。

不同实例的步骤和规则来源使用唯一身份；采集、断言和运行时修订仍只作用于当前实例。串行执行、浏览器按实例初始化及释放、停止和隔离规则沿用当前机制。原始输入及展开快照保存在插件计划/账本中，执行时不重新读文件；不写入 DSH 原始会话日志。

JSON 输入保持原有结构和行为；纯接口用例不调用 Playwright。最终仍生成一份集合报告，逐实例统计，原始用例数量与执行实例数量分别展示，不能把数据行或未执行实例漏计。

## 验证与边界

验证文本/Markdown 用例数、标准 CSV、精确替换和错误输入；验证批准前无业务工具、草案修改与旧审核拒绝、实例及规则隔离、跨实例成功/失败统计、原始数据不变和报告重建一致。在本地 DSH 独立环境实测 TXT、多层 Markdown、CSV 审核及 httpbin 请求，检查真实对话和报告页面，再保留已有单用例/JSON 回归。

不增加 Excel、目录扫描、多文件列表或表达式模板。大批输入仍受宿主上下文和运行预算约束，不能静默截断用例或参数。CSV 内容会成为模型上下文和报告材料，用户应使用适合测试环境的数据。现有 API 能力仍是 GET JSON，本次不扩大请求方法范围。
