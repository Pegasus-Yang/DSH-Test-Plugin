# RunBridge MCP 实施与验收计划

[目录](README.md) · [对接方案](对接方案.md) · [能力差异](能力差异与改动清单.md)

## 交付标准

成功标准是实际 DSH 的同一对话运行 TXT 或 Markdown 用户用例，通过 Hub MCP 在虚拟机创建浏览器、观察并操作页面、程序采集实际业务值、显示同一页面画面、生成一致报告，最后确认该远程会话释放且资源可再次使用。CSV 批次按既有审核与逐实例规则执行。

基础闭环只承诺被现有工具覆盖的表单场景；完整替代须明确批准的用例集合，补齐其所需工具并通过回归。截图刷新和持续采集分别验收，不能以 MCP 图像块、静态图片或单元测试代替实际浮窗与运行中画面。

## 环境准备

保留 Hub 为 `http://192.168.20.1:49762`。2026-10-13 22:52（Asia/Shanghai）的只读请求确认 health 返回 200、mcp 返回 404。服务项目同日 21:32 的记录指出虚拟机为 `pegasus@192.168.20.129`，目录 `/home/pegasus/runbridge-visual-test-20261012-171400`，Node 资源为借用的 `vm-chrome`，旧 access 文件均已过期；这些虚拟机状态在本轮没有重新 SSH 核验。

这套部署不能直接用于新建受管理浏览器的 MCP 验收。实施时先记录已有进程和数据归属，再建立专用 MCP Hub、受管理 Node 资源和短期访问许可。优先使用独立身份、目录与测试页面，避免为验收覆盖现有借用浏览器的 Profile、CDP 配置或历史数据库。

Hub 使用 `mcp` extra 和 `--enable-mcp`，保持单 ASGI Worker；Node 准备 Playwright `1.63.0` 的 npm 运行时、可用 Chromium 和中文字体，并声明 `MANAGED_CHROMIUM`、`READY/FREE`。节点所有者签发该资源的短期 access grant，插件从不提交的本机文件读取。启动窗口与 headless 由 Node 所有者配置，插件不覆盖启动参数。

被测页面必须从虚拟机可达。浏览器导航到虚拟机 `127.0.0.1` 是远程机器的回环地址；现有 HTTP 采集仍在 DSH 宿主，应分别确认两侧网络可达性。GitLab 用例沿用专用账号、固定种子、私有数据与本轮归属清理规则。

## 分阶段实施

| 阶段              | 实施内容                                                                                                               | 完成证据                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| P0 接口探针       | 固定 DSH 已发布版本；用真实 DSH MCP 客户端发现 12 个工具，核对结构化结果、图像原始值和错误投影；建独立虚拟机受管理环境 | 无有效 token 拒绝；正确 grant 能启动、截图并释放；版本和环境记录                    |
| P1 资源与执行     | 配置后端、来源冻结、当前实例句柄；同 Agent 操作转交、直接工具门禁、原子动作记录；启动响应未知处理                      | Markdown 基础表单在虚拟机产生实际服务端变化；工具和操作记录对应本次 session/page    |
| P2 可信采集与恢复 | 适配现有读值；需要兼容既有 DOM 时添加固定 browser_capture；严格关闭确认、取消和远程恢复                                | 固定预期的程序断言；故意错误预期得到 FAIL；UNKNOWN 不标释放成功；旧后端相关回归通过 |
| P3 截图显示       | 服务端只读截图任务和缓存；同源图片、既有浮窗、周期截图标识、陈旧清图                                                   | 动作前后画面确实变化，中文可读；收到的截图与当前 page_id 相符；UI 切换与结束清图    |
| P4 持续画面       | 探测同 Page CDP 截图；扩展 Hub 受管理来源、页面映射与 WS 发布；插件消费现有封包                                        | 等待中的画面继续变化；慢消费者不阻塞操作；源切换无串图；清理后无采集任务和流        |
| P5 回归与版本交付 | 补齐批准用例所需原子工具；GitLab Markdown UI 与接口、CSV、安装包、文档和发布收尾                                       | 全部规定验收完成，版本与运行记录一致，本地 commit 和附注标签可审核                  |

每阶段结果保持可复查。P0 无法证明已发布 DSH 的图像和错误合同时先收敛接口；P4 同页探针失败时评审 Node 专用 CDP 备选及实际成本，不以反复启动本机浏览器代替虚拟机证据。

工程估算：P0–P3 约 4–7 个工作日；含 P4–P5 和选定常用操作约 8–14 个工作日。估算基于单人、复用既有报告与浮窗、专用虚拟机环境可用、Hub 同页采集路线成立；不包含全部 Playwright API、远程录像或任意公网部署。探针后再更新估算。

## 测试与记录

单元测试集中验证真实语义边界：结构化解析、truncated、归属检查、释放 PENDING/UNKNOWN、封包拆解、陈旧帧和代次失效。使用实际 Host 工具管线覆盖作用域、审批、拒绝、取消、在途结算及原工具调用，不只模拟 HTTP 返回成功。

真实联调用专用虚拟机受管理浏览器和独立业务页，记录 DSH/plugin/Hub/Node/Playwright 版本、节点和资源、会话、PNG 摘要、独立业务状态及清理核对。画面实际可解码且浮窗可显示，两项都要验证。凭据和原始私有数据放在忽略目录，公开验收只保留脱敏事实。

功能交付按项目约定更新使用与配置、当前架构、执行交互、故障处理、changelog；重要版本同步 package.json、运行记录中的 plugin_version、已提交 dist、附注标签和提交日期。仅做本地提交与标签，远端同步由用户审核后进行。
