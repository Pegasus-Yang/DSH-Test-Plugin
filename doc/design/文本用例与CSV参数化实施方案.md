# 文本用例与 CSV 参数化实施方案

日期：2026-10-04。依据：[修改方案](文本用例与CSV参数化方案.md)。目标版本：0.6.0。

## 实施顺序与提交

| 阶段 | 内容 | 完成检查 |
| --- | --- | --- |
| P0 | 保存修改方案和本实施方案，更新导航 | 需求映射、入口和组合语义明确；先提交文档 |
| P1 | 文件解析、CSV 和参数展开 | 纯函数测试覆盖正常/错误输入，命令参数和路径边界通过；提交输入层 |
| P2 | 多实例文字规划、原生审核、来源与报告 | 不遗漏实例，计划与参数不可被模型替换，原有单任务和 JSON 回归；提交执行集成 |
| P3 | 中英文指南、示例与打包 | 命令和示例可解析，版本一致，构建、全部测试及包检查；提交文档与发行配置 |
| P4 | 独立 DSH 网页验收与问题修复 | 真实 TXT/Markdown/CSV、审批修改、断言和报告核对；修复及记录分别提交 |

## P1：输入与展开

新增 `case-input.ts` 负责 UTF-8 文件读取、路径限制、TXT 行解析、Markdown 根列表解析、CSV 解析和单次占位替换，命令层只选择输入方式。采用成熟的 Markdown/CSV 解析库，避免用正则解析嵌套列表或用逗号分割 CSV。

输入快照包含文件路径/原文、共享背景、原始用例及行号、表头、每行参数和展开实例。生成身份使用顺序编号，不依赖模型命名。路径读取复用 realpath 工作区边界；JSON 入口保留原行为。

测试要求：

- TXT 空行、BOM、CRLF、空文件与原始行号。
- Markdown 有序/无序根列表、多个列表、嵌套列表、代码块里的伪列表、结构化内容、多段落和共享说明。
- CSV 引号逗号、双引号转义、多行字段、中文列、前导零、空字段、额外列、空/重复表头、缺列、多列、无数据。
- `${参数}` 多次出现、缺列、值中再次出现占位符不递归、展开顺序和数量；参数不能改变已识别的用例边界。
- quoted 路径、越界和符号链接；错误输入不启动 Agent。

## P2：原生规划与执行集成

`NativeTests.start` 增加可选输入快照，旧入口保持兼容。多实例上下文在 systemPrompt/test_current 中由程序提供；`test_submit_plan` 对文件/参数化模式使用简洁的多实例 schema，模型只填写每个实例的 name/rationale/steps，并引用给定 instance_id。

`text-plan.ts` 验证标识集合与输入完全一致，并按输入顺序构建独立内部 case。为步骤和规则来源生成全局唯一 ID；保留原始模板、CSV 和展开任务，不能将思路文字当作额外断言授权。

审核 Markdown 从快照和草案生成，展示完整数量、参数、展开任务及各实例步骤。原生批准只冻结当前草案；等待期间禁止业务操作。普通文件入口的通报守卫覆盖全部实例，不再只检查第一条。单任务文字模式和 JSON 模式沿用原接口。

报告在每个实例增加可展开的来源与参数说明，集合区分源用例数和实例数。复用既有转义、下载、证据、实例状态及重建；无需额外报告服务。

集成测试要求：

- 两条用例、两行数据形成四个实例，缺失/重复/未知计划标识拒绝。
- 批准前无执行，修改后旧审核内容拒绝，新草案批准后顺序执行。
- 参数和原文由程序生成，模型的步骤修改不覆盖输入快照。
- 两实例分别产生不同可信观察，断言使用对应预期，PASS/FAIL 分开统计；一实例普通断言失败不污染下一实例。
- 动态步骤、采集、追加断言及浏览器清理保持实例隔离。
- 同会话停止、收尾、报告链接和账本重建回归；文件读取后的磁盘修改不影响冻结数据。

## P3：示例、文档与发行包

增加简单 TXT、多层 Markdown 和 CSV 示例，采用 httpbin GET JSON，附浏览器文字用例。更新中英文 README、使用说明、安装说明、当前架构及版本号；旧设计验收记录保持原貌。

运行类型检查、构建及全部单元/集成测试。校验示例解析、文档链接、发行包所含文档和依赖，固定输出 `artifacts/package/dsh-test-plugin.tgz`。包、调试及验收数据继续 Git 忽略。

## P4：真实验收

通过公开 CLI 安装到独立 DSH home，并用独立浏览器窗口在真实对话输入框操作；不直接写会话数据或通过 RPC 绕过用户入口。

1. TXT 两条接口用例：通报完整、串行执行、两个结果和报告。
2. Markdown 顶层列表含嵌套步骤/代码块：识别正确数量，原始结构保留，模型能按内容执行。
3. CSV + 模板：计划阶段展示参数名、所有值、展开原文及实例数；要求修改文字步骤后再次审核，批准才发出请求。
4. CSV + 文件：多用例 × 多数据行的数量和对应关系正确；报告能定位源用例与数据行。
5. 校验真实返回值、确定性断言、原始计划、账本和报告一致；界面、最终链接及静态报告可用。

有失败时保留原始结果、定位原因并补必要回归；不能将构建成功或人工补发 HTTP 请求当作 DSH 用例通过。实际未覆盖项明确记录，不扩大验收结论。
