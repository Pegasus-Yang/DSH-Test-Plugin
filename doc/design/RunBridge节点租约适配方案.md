# RunBridge 节点租约适配方案

本轮按 Hub 会话同步的已确认规则实施，目标为插件 0.15.0、Hub 0.9.1、Node 0.8.1（租约合同从 0.9.0／0.8.0 引入）。Hub 与 Node 由对应项目会话维护，本仓库只调整插件。0.14.1 已完成本地提交和标签，作为本轮前置基线保留；本轮验证后另建本地提交与附注标签，不推送。

具体接口以 Hub 仓库的 `doc/reference/Node使用权租约接口.md` 为准；本记录只描述插件职责。共享 hub_token 仅供资源目录和申请，access_token 供本次整 Node 租约执行、查询、续租和释放，不增加用户、账号或 ACL。

## 配置与准备

- 保留“现成访问文件”，兼容现有 JSON／YAML 字段，不把它当作永久授权；使用该文件执行浏览器任务后，整批结束主动释放。
- 新增明确的“Hub 自动领取”，独立填写 Hub 私有认证文件路径和目标 node_id，不把两种文件混合猜测。Hub 文件仅含 hub_url、hub_token，模板默认带注释 YAML，凭据只在宿主读取。
- 节点租期可省略，由 Hub 采用默认值并受其配置上限约束；与每条用例 1～3600 秒的浏览器会话租期分别展示和校验。
- 自动模式规划／审核只读取 pool 工具目录，使用同源 MCP 声明。设置检测同样只读，不能声称已领取或已建立执行连接。实际领取后再用 tools/list 核对目录，定义不一致时先释放再结束。

## 执行与身份

1. 完成规划、原生审核和计划宣告后，在首个可信浏览器初始化前申请；纯 API 不申请。
2. 每次完整 TXT／Markdown／CSV 运行共用一份 Node 租约，逐用例仍独立初始化及关闭浏览器。
3. 领取请求身份先持久化，再发送唯一 request_id；首次令牌只接收一次。响应遗失或重复申请没有令牌时记录 UNKNOWN，不重试申请或领取新租约继续旧步骤。
4. 用原节点令牌查询／按需续租，续租不刷新空闲计时。状态查询、模型思考、审核等待和持续画面不构成设备活动。
5. 运行中租约失效时停止旧业务，保留原 grant/session/request 证据。下一次新任务可以重新领取，原任务恢复不能换身份。

自动领取的执行凭据保存在 outputRoot 下独立的私有目录，权限限制为当前用户；不放入运行报告目录、账本或模型上下文。未确认释放时保留恢复所需的原凭据；确认 RELEASED／COMPLETE 后才回收本轮自动生成文件，不改写用户提供的访问文件。

## 收尾与恢复

- 正常完成、取消、失败和正常卸载都等待原会话与节点租约收尾；关闭浏览器或 MCP 断开不代表节点已归还。
- DELETE 后轮询原租约，只有 RELEASED 且 cleanup=COMPLETE 才确认归还；RELEASING／PENDING 继续等待，QUARANTINED／UNKNOWN 保留隔离。
- 报告封存等待本次收尾结果，分别显示业务断言和节点归还状态。未确认归还不把原有业务 PASS 改成业务断言失败，但整批必须显示未完成／隔离。
- 恢复只使用原访问文件与原 grant_id。已结束租约可以查询和重复释放，不能操作新持有者。没有原令牌的未知领取进入人工处置，不用共享 Hub 凭据强制清除占用。

## 验证与交付

先完成文件及 HTTP 合同回归，覆盖双模式、只读准备、首次响应丢失、状态身份核对、续租与释放终态；再验证原生审核、API 零领取、CSV 整批复用、异步报告封存、取消与恢复。之后用独立 Hub／Node 验证实际设备归还和下一批可再次领取。

正式交付只构建一个候选包，三版 DSH 独立 profile 验证同一摘要；完整确定性矩阵、真实模型及 GitLab Markdown UI／接口、报告重放与 Agent 空闲门禁按既有规范执行。同步当前中英文使用／部署／恢复文档、版本、dist、changelog 和最终验收记录，保留历史记录。
