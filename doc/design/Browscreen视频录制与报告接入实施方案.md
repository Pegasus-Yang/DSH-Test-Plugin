# Browscreen 视频录制与报告接入实施方案

方案日期：2026-10-05，Asia/Shanghai。状态：**用户已批准实施；当前实现及验证结果见[录像验收记录](../project/浏览器录像与报告验收.md)**。

插件设计基线：本地提交 `21eedae`，包版本 `0.9.2`。Browscreen 接入基线：正式 PyPI `0.3.0`。本文保留批准时的设计和调研范围；当前实现事实见[当前架构](../architecture/当前实现.md)与验收记录。

## 1. 目标与已确认行为

在当前对话的测试执行过程中，自动记录实际浏览器画面，并在对应测试报告中播放、拖动进度和下载录像。程序断言继续依赖已有可信观察，视频用于查看执行过程。

用户已确认：**录像独立开关，默认关闭**。开启录像后，隐藏浮窗、不显示浮窗或关闭页面，都不能成为停止录制的条件。开关修改在下一次测试生效。

接口测试、没有浏览器画面的任务，不启动录制，也不在报告中出现视频选项卡、播放器、截图预览入口或“没有视频”占位提示。混合测试批次按每个实例分别判断；不能因为批次中有一个 UI 用例，就给其他接口实例显示录像区域。

保留当前四个测试命令、原生 Agent、原生停止与清理、设置页处置和共享浏览器串行限制；首版不新增录像斜杠命令、不合并多个实例的视频、不实现多对话独立浏览器或 App 原生录屏。

### 2.2 参数及约束

| 参数 | 使用方式与约束 |
| --- | --- |
| `--record` | 显式开启录制，默认不录制；需要安装 `browscreen[video]` |
| `--record-output PATH` | 完整 `.mp4` 文件路径，必须同时提供 `--record`；父目录已存在，文件不能已存在，不覆盖 |
| `--work-dir PATH` | 已有 CDP 交换目录；不是视频输出目录 |
| `--interval-ms` | 默认 300 毫秒，控制采集目标间隔；无独立 `--record-fps` 参数 |
| `--connect-wait-timeout-s` | 默认 60 秒，启动或恢复到有效帧的预算；不是最长录像时长 |
| `--host` / `--port` | 继续使用插件管理的本机地址和采集端口 |

插件将显式传入运行目录中的绝对视频路径，例如：

```sh
browscreen --work-dir <CDP交换目录> \
  --host 127.0.0.1 --port <设置端口> \
  --connect-wait-timeout-s 60 \
  --record --record-output <本次运行目录>/evidence/browser-<实例标识>-<片段标识>.mp4
```

输出是无音轨的 H.264 / `yuv420p` MP4，复用已有合成 PNG，不额外启动截图循环。第一张有效帧才作为视频时间零点，规划和连接等待不录入视频。画面使用实际采样时间轴；连接中断期间可能保留上一张已知画面，不能将其解释为持续正常采集。

默认约 300 毫秒的目标采样间隔不保证每秒采样次数；编码或网络等待可能降低实际频率。首版不增加高帧率配置，也不承诺记录每一个浏览器动画中间帧。视频包含 PNG 已有的指针合成内容，本插件原本未接入的鼠标轨迹不因录制自动产生。

### 2.3 退出与结果识别

必须发送 SIGTERM 或 SIGINT 并等待编码刷新、容器关闭和进程结束。无有效帧时删除空文件；部分录制和无法确认收尾的残留文件不能当作正常完整视频。

0.3.0 的公开接口没有结构化录像状态查询，也没有独立开始、停止录像接口。最终结果由 stderr 的日志摘要输出：

- `录制完成，视频文件：…`。
- `录制提前终止，已保存部分视频：…；原因：…`。
- `未生成视频：未获取到有效截图`。
- 录制失败或未完成收尾的说明。

不能只判断退出码为零：Uvicorn 的正常 SIGTERM 退出也可能表现为信号退出。插件应结合自己发起的终止方式、完整日志摘要和文件检查确认结果，并等待 `close` 事件确保 stderr 已读完。

首版在已核实的 0.3 系列 CLI 上解析上述摘要，使用流式 UTF-8 解码，不能用截断的诊断尾部推断结果。归档路径由插件预先生成，不能信任日志中的任意路径作为复制或下载目标。若后续 CLI 改动日志协议，需重新验证；结构化结果接口作为后续优化点，不要求本次修改 Browscreen 项目。

## 3. 用户设置与安装

在现有“设置 → 测试插件”中新增“录制浏览器操作视频”，默认不勾选。复用已有 Browscreen 命令路径、端口和 Playwright 选择，不新增源码目录或视频输出目录配置。

| 实时预览 | 视频录制 | 实际浏览器用例的行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 不启动 Browscreen |
| 开启 | 关闭 | 现有预览；不传录制参数 |
| 关闭 | 开启 | 后端持续录制；不显示实时画面浮窗 |
| 开启 | 开启 | 同一个进程提供预览和录像；隐藏浮窗不停止录制 |

以上四种设置下，纯接口实例都不启动 Browscreen。采集还需满足当前实例拥有浏览器上下文、CDP 归属匹配、单活动页面及端点可达。无 CDP 时不制造空播放器或浮窗。

拟将兼容范围统一升级至稳定版 `>=0.3.0,<0.4.0`，在检测、设置提示、文档与测试中同步。录制可选，但新版最低 CLI 版本统一为 0.3.0，避免维护两套录制参数兼容分支。

发行后用户在 DSH 宿主安装带视频依赖的包：

```sh
uv tool install --force --python 3.14 'browscreen[video]==0.3.0' \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
browscreen version
```

普通预览用户仍可安装不带 extra 的 `browscreen==0.3.0`。`version` 和 `--help` 不加载 PyAV，现有“检测安装”成功只证明 CLI 版本可用，不能声称视频依赖已验证。设置页应明确这一点，实际录制启动失败时提示安装 `video` extra。

## 4. 运行、归档与报告时序

### 4.1 服务端驱动采集

现有 `PreviewManager.refresh()` 由进度接口读取触发；不能沿用这一路径作为录制启动的必要条件。

录制启用时，在当前实例实际登记浏览器资源后，由服务端启动归属检查和采集轮询，复用已有 CDP 校验、启动预算及并发探测保护。页面是否可见、是否打开浮窗、是否存在前端进度轮询，都不影响录制。资源释放、实例切换、采集终止、测试结束及插件卸载停止对应服务。

只有预览开启、录像关闭时，可以保留现有展示按需读取逻辑。开启录像后，前端读取复用后端采集状态，避免启动两份进程或重复采集任务。

采集就绪与预览启用需要分开：仅录像模式下，后台可以收到有效帧，但对外进度快照不能发布可自动打开浮窗的 `preview.ready`。预览组件及“显示实时画面”入口仍只在实时预览开关开启时出现。

### 4.2 按实例及片段保存

录像直接写入本次 `run` 的 `evidence/`，不用系统临时目录。每个实例、每次实际重建采集进程使用唯一文件名。

同一页面普通导航保持同一片段。实例更换、CDP target 更换等导致采集进程重建时，收尾旧片段并建立新片段，不把不同实例混入一个视频，也不覆盖旧文件。一次暂时断连由 Browscreen 原有恢复逻辑处理；多活动标签仍沿用当前停用采集规则。

归档记录至少包括：片段标识、运行及实例标识、浏览器目标、第一帧时间、停止时间、文件完整性状态、相对路径、文件大小和 SHA-256。能可靠从 MP4 索引读取时记录视频时长。视频时长从首帧开始，不能冒充包含规划等待的整轮用时。

已归档的视频作为可选证据，`media_type` 为 `video/mp4`、`redacted` 为 `false`。文件原始内容不自动脱敏；对外分享报告前由操作者检查实际画面。

### 4.3 收尾后再生成正常报告

正常路径为：浏览器资源释放 → SIGTERM → 等待采集进程与编码收尾 → 确认视频状态和文件 → 写入录像事件、结果及证据索引 → 生成 HTML。

不能继续使用 1.5 秒就 SIGKILL 的固定录制退出逻辑。录制收尾复用已有清理预算及剩余期限，不重新开始一份无限或额外业务预算；纯预览仍可保留现有快速退出行为。

正常完成、失败、取消、实例切换和卸载进入统一的录制结算方法。普通 `test_finish` 和同会话清理可以等待结算；紧急截止路径按原有期限封存业务结果，未确认收尾的文件记为失败或不完整残留，不加入可播放附件。

录像结算事件必须属于原运行和实例，不能依赖当前可变 `owner`。原始与重建报告均读取已保存记录，不重新录制或调用模型。迟到的媒体清理不能更改封存断言、业务状态或隔离结论。

### 4.4 录制失败与预览隔离

| 情况 | 处理 |
| --- | --- |
| 缺少 PyAV、编码器不可用或输出文件准备失败 | 本次录制失败并提示原因；若同时开启预览且确认失败来自录制准备，允许一次去掉录制参数的预览启动；不循环重试 |
| 运行中编码错误 | Browscreen 已支持停止录制、继续截图；插件保留预览并记录最终录像状态 |
| 无有效帧 | 不登记视频附件，不显示空播放器 |
| 有可读索引和有效视频轨道，摘要为部分录像 | 显示片段，明确“部分录制”及原因 |
| SIGKILL、日志缺失、文件空、MP4 索引或轨道不可读 | 不标记可播放；实际 UI 用例可显示一次录制异常说明 |
| 业务取消 | 保留取消前的视频，并注明对应测试已取消；文件正常封装不代表业务完成或 PASS |

录像故障不改写程序断言。采集进程无法回收时，继续使用现有资源处置与门禁，不以隐藏录制错误掩盖仍存活进程。

## 5. 报告显示与 HTTP 访问

### 5.1 按真实证据条件显示

在实例详情新增“操作录像”，只有存在该实例已确认可读的 MP4 时才出现选项卡和播放器。使用原生 `<video controls preload="metadata">`，支持播放、暂停、拖动和下载；不自动播放。多片段按时间排列，标明完整性、时长及起止时间。

UI 实例录制失败时，可以在已有浏览器证据区域显示一次原因，但不渲染空 `<video>`。不能仅按计划文字包含“UI”“浏览器”等关键词决定显示；应依据实际浏览器资源、画面和归档事实。

纯 API 报告保留步骤、断言、响应、附件、耗时，不生成录像选项卡、录像占位说明或截图预览对话框。现有 `report.ts` 无条件输出图片对话框，`report-client.ts` 无条件绑定其元素，需要一起改为有图片时才挂载和绑定。

混合批次从 UI 实例切换到 API 实例时，若原先选中了录像选项卡，应回到该实例已有的“步骤”等可用选项卡，避免出现空详情。隐藏实例或切换录像片段时暂停原视频，避免声音或后台播放状态残留；当前视频本身无音轨。

### 5.2 独立 MP4 与受保护的分段读取

HTML 中使用相对视频路径，例如 `evidence/browser-xxx.mp4`，不把整段录像编码为 base64；图片继续沿用现有处理。离线查看需复制完整运行目录，包含 HTML、MP4 和其他证据。

`ReportAccess` 继续复用宿主认证、GET/HEAD 限制和文件边界。增加 `video/mp4`、文件大小与流式读取，支持浏览器常用的单段 HTTP Range：

- 正常整文件读取返回 200。
- 有效字节区间返回 206、`Content-Range` 和该段长度，允许拖动时间轴。
- 越界区间返回 416；HEAD 返回对应文件头。
- HTML 的 CSP 增加受限的 `media-src 'self'`，保留现有 sandbox，不开放任意远程视频源。

`report-rebuilt.html` 使用同一组已归档相对路径。元数据或文件缺失时给出真实状态，不能从另一个实例的视频回退补齐。

## 7. 验收标准

### 自动回归

1. 默认关闭，不添加录制参数、不创建文件；纯 API 即使全局开关开启也不启动采集或写入录像字段。
2. 有效当前实例与 CDP 才启动；无前端轮询、页面隐藏、无浮窗均不影响录制。
3. 预览和录像同开只创建一个进程；隐藏浮窗不会终止录制；实例和 target 切换不会串片。
4. 完整、部分、无帧、缺少依赖、写入失败、信号退出、强制退出和摘要 UTF-8 分片均按实际状态结算。
5. 录像证据归属、相对路径、SHA-256、结果快照和事件顺序一致；重建使用原记录且保留业务结果。
6. API HTML 无视频、截图对话框和媒体占位说明；混合批次中 API 实例无录像入口，切换后选项卡有效。
7. 视频 MIME、HEAD、整文件与 Range；文件越界、缺失和无效区间；CSP 下的播放和离线目录播放。

### 真实环境

使用独立的公开 npm DSH、独立 profile 和正式 PyPI `browscreen[video]==0.3.0`，不替换用户运行中的 3080 服务。

- UI 用例实际执行，生成 MP4，确认画面变化；报告播放器触发 `loadedmetadata`，实际播放到正时间，能 seek 和下载。
- 仅录像、不显示预览，及关闭/隐藏 DSH 页面仍持续记录；恢复后能查看录像。
- 两个浏览器实例、纯接口实例及混合批次分别验证归属和条件显示。
- 取消、失败和必要浏览器清理均保留真实业务状态；部分或未确认收尾的视频不被标作完整录像。
- 复制整个运行目录，分别打开原始和重建报告验证离线播放。
- 不带 `video` extra 的环境验证录制安装提示和可选的预览回退。
- 验收后停止自有服务，检查安装包、入口与已构建文件一致，再创建本地提交供审核；发版与标签另按发布约定处理。

## 8. 本轮核对范围

本轮已完成：CLI 版本/帮助、参数和源码流程、PyAV 与 H.264 编码器加载、PyPI 元数据、发行 wheel 哈希及相关模块字节比对、插件当前采集和报告链路分析。

本轮尚未执行插件录制、报告视频播放或上述改造回归；没有升级本机默认命令，没有修改两项目的运行代码，没有启动或更换用户 DSH。原始核对数据保存在忽略的 `.local/video-recording-research/`。

参数及实现来源：正式 0.3.0 wheel 中的 `browscreen/main.py`、`models.py`、`recording.py`、`capture.py`、`app.py`；插件基线中的 `src/preview.ts`、`preview-setup.ts`、`native-test.ts`、`report.ts`、`report-client.ts` 与 `report-access.ts`。公开发行信息见[PyPI 0.3.0](https://pypi.org/project/browscreen/0.3.0/)和[发行元数据](https://pypi.org/pypi/browscreen/0.3.0/json)。

## 9. 实施中的必要补充

真实报告保留原有 opaque sandbox。宿主登录 Cookie 使用 `SameSite=Strict`，无法依赖它为这种页面中的媒体请求认证。为保证实际播放，同时保持隔离，只在已认证 HTML 的响应中签发该 MP4 的 HMAC 只读票据；限文件路径及 GET/HEAD，24 小时过期，重启失效。票据不写入离线 HTML，不开放其他附件或业务接口。

同一隔离策略下，浏览器可能忽略跨来源的 `download` 属性。视频下载链接增加专用下载参数，由服务返回 `Content-Disposition: attachment`；播放器仍使用流式 MP4 和单段 Range。上述调整以真实播放与下载验证为依据，业务断言及执行链路保持原设计。
