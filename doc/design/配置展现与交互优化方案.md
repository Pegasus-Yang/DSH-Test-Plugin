# 配置展现与交互优化方案

日期：2026-10-23（Asia/Shanghai）。状态：已按用户确认的方案完成本地实施与验收，保留访问文件方式，暂不增加四项手工录入。范围：测试插件的浏览器连接、预览录像、环境处置与报告维护设置。

以下保留设计阶段的比较、审查与建议；实际完成范围、验证和边界见[0.14.0 版本验收](../project/0.14.0版本发布验收.md)。

## 结论

本轮推荐**保留 Node 签发的访问文件作为连接来源，将界面改为有引导、有解析结果、有检测反馈的配置流程**。界面同时提供格式说明与可复制、可下载的空白模板。暂不把 Hub、node_id、grant_id、access_token 四个字段直接存入普通插件配置。

用户进入页面后，应能看到连接到哪个 Hub、哪个节点、哪个资源，以及配置是否保存、最近是否检测成功。无需先打开文档理解 JSON，才能判断自己配置了什么。

直接填写四项数据有使用价值，但会新增凭据接收、保存、回读与更换的职责。本轮的实际问题可以通过访问文件引导和检测解决，适合先做范围较小的一轮。若后续确认主要用户只会收到四项文本，再增加“手动填写”，由宿主安全保存为同一种私有访问文件。

## 配置方式比较

| 方案 | 使用收益 | 代价与边界 | 建议 |
| --- | --- | --- | --- |
| 直接在界面填写四项 | Hub 地址可见；有各字段提示；不必手工编辑 JSON | 用户仍需获得正确节点、许可和令牌；须新增秘密保存机制，避免普通设置回读出完整令牌 | 可作为后续备用方式 |
| 只增加文件模板 | 改动较小；延续现有访问文件与 Node 签发流程 | 仍需手工搬运和编辑，不能确认选错文件或网络是否可用 | 属于必要补充，不能单独解决问题 |
| 访问文件引导、解析摘要和连接检测 | 复用已签发的完整身份；用户可直接确认 Hub、节点与错误原因；保持现有凭据边界 | 需要受当前登录态保护的服务端解析与检测能力 | 本轮推荐 |

Node 已能用 `grant --output` 生成访问文件，因此主说明应优先引导“向 Node 所有者取得访问文件”。空白模板用于解释字段和配合已有授权信息填写，不会生成许可，不应使用户认为随便填写 grant_id 就能授权。

## 推荐的页面结构

沿用 DSH 现有设置容器、主题颜色、字号体系、输入框与按钮风格。此次调整信息顺序、状态表达和操作路径，不另造视觉体系。

| 顺序 | 区域 | 常态展现 | 异常展现 |
| --- | --- | --- | --- |
| 1 | 浏览器连接 | 本机／远程选择、连接来源、当前配置摘要、检测与保存状态 | 对应字段错误、连接失败原因和下一步 |
| 2 | 画面与录像 | 根据同一份浏览器模式草稿显示可用选项 | 显示依赖缺失和不支持的能力 |
| 3 | 环境处置 | 一行“无待处理资源”，低强调 | 存在隔离时置顶显示原因、遗留运行及“处理并释放” |
| 4 | 报告维护 | 默认折叠“重建历史报告” | 用户主动展开后输入运行 ID 并执行 |

连接和画面区域共用一份草稿及一组“保存浏览器设置／放弃修改”按钮。报告重建、资源释放属于独立操作，不混入配置保存。模式切换即时更新相关内容，已保存的生效模式另用文字注明。

## 远程连接的具体流程

### 1. 取得或准备访问文件

字段名改为“访问文件（DSH 运行机器上的 JSON）”，示例路径为 `/path/to/runbridge-access.json`。明确区分 DSH 运行机器和当前打开网页的电脑，避免远程部署时误填浏览器本机路径。

字段旁提供“查看格式”“复制模板”“下载空白模板”“如何获取访问文件”。展开后给出完整示例与字段说明：

```json
{
  "hub_url": "http://hub.example:8787",
  "node_id": "node_example",
  "grant_id": "grant_example",
  "access_token": "<Node所有者签发的访问令牌>"
}
```

| 字段 | 用户需要知道的内容 |
| --- | --- |
| hub_url | Hub 基址，插件会拼接 MCP 路径；不要把带 `/mcp` 的完整端点直接当基址 |
| node_id | Node 所有者提供的节点身份，不是电脑名称或 IP |
| grant_id | 与本份访问令牌配套的许可 ID，不是自定义备注 |
| access_token | 已签发许可的访问令牌，不是 enrollment.token；模板中的占位文字不能直接使用 |

支持保留 Node 导出的可选 `expires_at`。界面可显示“文件标注的到期时间”，服务端验证结果仍是授权是否有效的依据。Hub 的反向代理前缀应按既有基址规则保留，不能为了去掉 `/mcp` 粗暴删除所有路径。

这类说明应放在字段附近并关联到控件，不依赖会消失的 placeholder。该原则与 [W3C 表单说明指南](https://www.w3.org/WAI/tutorials/forms/instructions/)一致。

### 2. 读取并检查文件

提供“读取配置”操作，由 DSH 服务端读取，不把整个文件内容返回网页。检查可读性、JSON 格式、必需字段、地址及身份格式；错误在文件字段旁说明。

对于本轮实际误用，建议文案为：“文件内容不是连接 JSON。请使用 Node 所有者签发的访问文件；enrollment.token 用于节点登记。”不能仅根据文件扩展名判断内容类型。

读取成功后，展示只读的 Hub 基址、实际 MCP 端点、节点 ID、许可 ID和“访问令牌已配置”。默认不把令牌值回读到浏览器，也不在错误或日志里输出它。文件缺字段时明确指出缺少哪个字段，不能只报“配置无效”。

### 3. 检测连接

“检测连接”针对当前草稿执行，不要求先保存错误配置。通过 MCP 握手、工具清单和只读 `node_inspect` 核对授权节点、可用资源及状态；关闭这次临时 MCP 连接。

检测不调用 `browser_start`，不启动 Chromium、不占用浏览器资源、不执行业务，也不解除既有隔离。受管理资源可在检测后选择授权结果中的项目；离线配置仍保留手工填写资源 ID 的能力，复用现有 resourceId。

结果要分层说明：文件解析通过、Hub 可连接、节点是否在线、所选资源是否可用。节点离线或资源被占用时，不把它们统称为认证失败。检测成功仅表示当时通过，显示时间；改动路径、资源或文件内容后，应撤销旧检测结论并提示重新检测，取消或迟到的结果不能覆盖新草稿。

### 4. 设置运行选项

资源默认仍使用当前 `chromium` 约定，显示其所属节点。租期保留现有 1～3600 秒限制，默认 1800 秒旁显示“30 分钟”；说明它覆盖执行与收尾，区别于工具超时。许可期限不足时给出明确提示，不替用户签发新许可或自动续租。

“显示实时画面”与本机预览使用一致命名；远程模式只显示其实际支持能力。远程录像以简短“不支持”说明展现，不显示可误开启的录像开关。

### 5. 保存并确认生效

同一份浏览器草稿一次保存连接和相关画面选项，复用现有配置修订机制。格式错误阻止保存；网络暂时不可达时可保存格式正确的配置，但标注“已保存，连接未验证”，不能显示“连接成功”。

保存成功提示：“已保存，下次测试生效；当前测试继续使用原连接。”已有连接和运行中的资源保持原身份。页面区分“未保存修改”“已保存”“最近检测结果”和“运行中使用的配置”，避免一个绿色状态承担多个含义。

放弃修改应恢复连接、资源、租期和画面选项的整份草稿。关闭设置或切换栏目时，对未保存内容提供“继续编辑／放弃修改”；若宿主暂不提供离开拦截接口，至少显示持续可见的未保存状态和显式放弃按钮，不能承诺宿主尚不支持的拦截行为。

## 可访问性与反馈

本轮确认主要控件已有可读标签、设置使用宿主主题，错误提示也有一部分 status/alert 支持。应保留这些基础。

需要改善的是：将格式与示例说明通过 aria-describedby 关联到字段，校验错误使用 aria-invalid 并关联可操作的错误信息；一般保存成功与校验失败不能始终共用同一种状态提示。本轮检查的本机 MCP 与端口字段没有关联其补充说明。

错误信息应说明出错字段、原因和修正办法，可参考 [W3C 表单反馈指南](https://www.w3.org/WAI/tutorials/forms/notifications/)。关键连接结论使用文字与状态标记共同表达，不能只靠颜色。保持可见键盘焦点，并在实现验收时补测窄窗口、200% 缩放、完整键盘顺序及屏幕阅读器。

截图不能证明完整 WCAG 符合性。本轮没有测量全部对比度，也未进行屏幕阅读器或全套键盘测试；这些是后续实现的验证项，不记为已通过。

## 手动录入的后续边界

若用户后续选择增加手动录入，四项字段提供中文含义与规范标识，令牌输入可临时显示但默认遮挡；Hub 明确区分基址与最终 MCP 端点。用户一次提交后由宿主写入私有访问文件，普通插件配置仍只保存文件引用，避免两套连接参数同时生效。

该模式须单独处理秘密保存、回读不泄露、替换失败保留旧配置、清除引用与撤销许可的区别，以及远程网页到 DSH 宿主的凭据传输。本轮不增加此能力。令牌不应持久保存在浏览器 localStorage，相关原则见 [OWASP HTML5 存储建议](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage)。

## 实施优先级与验证标准

| 优先级 | 建议范围 | 可验证的完成标准 |
| --- | --- | --- |
| 必须 | 文件格式、字段解释、模板与获取入口 | 首次使用者在设置页内能找到完整 JSON；清楚知道需取得真实许可；不会被引导使用登记令牌 |
| 必须 | 文件解析与连接检测、分层状态 | 本轮 enrollment.token 能立即被指出格式错误；检测期间 browser_start 调用为零；节点离线和资源忙分别展示 |
| 必须 | 同一草稿、统一保存、明确未保存状态 | 本机／远程切换后相关区域同步；一次保存完整浏览器设置；放弃恢复原值；修订冲突不覆盖他人配置 |
| 必须 | 状态语义及错误定位 | “无待处理资源”不表示 Hub 已连接；离线保存不显示已连通；错误能定位到对应字段 |
| 建议 | 页面排序、低频功能折叠、高级参数收敛 | 普通打开设置即可开始配置连接；报告与维护操作仍可找到，异常处置优先 |
| 建议 | 本机空状态、安装检测文案、只读说明、可访问性 | 无 MCP 时有真实下一步入口；检测范围表达准确；键盘和辅助技术获得同样的说明与错误 |
| 后续 | 手动填写四项、从浏览器上传文件等扩展 | 仅在用户确认需要后设计；复用同一访问文件合同，不增加并行生效的凭据来源 |

具体实现应复用 BrowserPreferences、现有配置修订能力、readRunBridgeAccess 和官方 MCP 客户端。主要影响设置页面、对应宿主解析／检测入口和使用指南；不需要修改 Hub/Node、不调整业务执行与断言、许可及清理语义。

回归需覆盖格式错误与缺字段、秘密不回显、检测不分配资源、检测取消及迟到结果、模式切换、整体保存／放弃、只读与修订冲突，以及保存后下次运行的配置绑定。重要交付仍按项目既有三版 DSH 验收要求执行。本轮只交付此方案与截图记录，不修改代码、日常配置或创建版本提交。
