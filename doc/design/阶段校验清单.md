# 阶段校验清单

本清单共 **56 项**，本轮已完成13项的对应验收，其余包含部分验证或尚未执行的子场景。执行日期、版本、证据及剩余范围见[开发与验收记录](../project/开发进度.md)。编写文档、阅读源码或示例文件可以说明设计依据，不能把功能项勾选为通过。

## 1. 执行与记账规则

- `[ ]` 表示未通过验收；只有实际执行、满足通过条件并填写证据，才改为 `[x]`。
- 在验收记录中用“未执行/通过/失败/阻塞/不适用”标记结果。不适用需写明范围变更依据，不算通过。
- 每条记录至少含检查编号、执行时间、执行者、插件/DSH版本、环境、实际结果和证据路径；失败附问题编号。
- 建议后续证据保存在实施工程的 `artifacts/validation/<stage>/<check-id>/`，按清单编号归档。这里仅约定路径，不表示文件已存在。
- 上游版本、工具版本或相关代码发生变化时，只复验受影响项和必要回归；保留上次记录，不覆盖失败证据。
- 阶段门槛是对应八项全部通过。阻断项未解决不进入依赖它的下一阶段；可以继续不依赖该项的合同或模板工作。
- 一个编号包含多个反例时逐个记录输入和唯一预期，全部满足才勾选该项；不能以“ERROR 或 INCONCLUSIVE 均可”替代合同判定。M1/M2 用固定事件和调度替身验证合同，M3/M4 再验证真实 runner；前期替身通过不代表宿主功能通过。
