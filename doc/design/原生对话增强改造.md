# 原生对话增强改造

## 目标与纠正（2026-10-03）

用户明确要求测试能力增强当前DSH对话：规划、追问、动作、审批、停止和收尾全部由发起会话的原生Agent循环处理。历史方案中的独立规划/执行/清理Agent和自制进度投影不再作为交互入口。

核实宿主公开规范：

- `packages/interaction/commands/README.zh.md`：命令本身不创建模型消息，命令记录不等于普通对话。
- `packages/core/agent/README.zh.md`：用当前 `Agent.followup()` 提交真实用户输入，`inject()` 添加已记录的模型上下文；`agent/turn-stopping` 支持有界补充指导。
- `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md`：框架驱动、插件计算；新增文本通过 `systemPrompt.section()`；通过 `tools/result` 观察最终结果；不新增无法声明兼容性的会话事件，不向聊天页或document.body直接追加DOM。
- `packages/core/tools/README.zh.md`：原生工具注册、策略和最终结果事件保留宿主执行/审批/展示链路。

以上路径相对本机deepseek-harness源码。可调用工具未提供宿主的cordis_inspect，因此以当前安装所链接的公开类型、文档和真实宿主验收核对接口。

## 实施约定

1. `/test` 和 `/test-run` 向接收命令的Agent提交用户输入，保持原生对话历史与工作区关联，不创建其他Agent，不重写会话日志或浏览器本地状态。
2. 插件仅在当前测试作用域贡献指导和工具，模型在正常循环中调用浏览器、提交冻结计划、采集观察、请求确定性断言及报告。原始消息、模型请求、审批和工具结果均由宿主记录及展示。
3. 采集继续从真实工具响应生成绑定证据，不接受模型填写实际值。沿用计划校验、比较器、脱敏、账本和HTML报告格式。
4. 停止先禁止新业务动作，等待原生轮次及已进入工具结算，再在同一会话发起预授权清理轮次。用户已确认这一行为；未能证明在途结算时不能启动清理。
5. 移除独立对话进度插件及全局报告提示。报告链接通过原生工具结果和模型最终回复提供，报告HTTP仍由宿主认证保护。
6. 模式与结果按发起会话隔离；新会话不展示旧结果。完成后撤销测试专用提示/工具/监听器，普通聊天不继承测试约束。

## 验收

- 全新会话第一条直接 `/test`，无需先发普通消息，能在侧栏保存、命名和恢复。
- 能看到原生推理/文本、Playwright工具请求、工具结果、断言与报告；后续用户消息正常延续同一会话。
- 新建另一会话无上次测试提示；切回、刷新、重启后原会话内容保留。
- 真实运行社区agent搜索用例，断言实际值来自采集且与报告一致；测试取消后在同一会话显示收尾。
- 自动化测试覆盖会话隔离、原生提交、观察可信性、取消与清理边界及作用域释放；打包检查不包含调试记录，分阶段提交Git。
