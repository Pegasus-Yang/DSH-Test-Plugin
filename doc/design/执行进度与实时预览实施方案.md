# 执行进度与实时预览实施方案

## 0.8.0 设置页补充

用户确认后，将原有手工预览接入补充为“设置 → 测试插件”的表单。启用开关、Browscreen 目录、采集端口和 MCP 实例使用整组 volatile 配置保存到当前 profile；未保存新字段时仍兼容旧 `preview`。字段与逐步使用方法见[配置指南](../user-guide/浏览器实时预览一步一步配置.md)。

实现顺序：声明配置与原生设置插槽，使用 configForms 保存；在下一次测试的共享环境门禁之后准备选中的 MCP，生成保留已有配置的初始化文件，通过 config-editor 正常重连；复用当前 CDP/首帧门禁和采集进程生命周期。启动准备保持互斥，配置错误只停用展示，命令行/home overlay 的高优先级限制不被绕过。

验证包含参数和环境保留、重复准备稳定、非法端口、非 Chromium 拒绝、启动互斥，以及真实设置页保存/刷新、接口无浮窗、直接 `/test` 的有效画面与结束清理。0.7.0 的实施阶段保留在下文。

日期：2026-10-04。依据：[可行性方案](执行进度与浏览器实时预览方案.md)。用户已授权按方案实施，并追加约束：只有可取得可用 CDP 时启用实时画面浮窗，API 或没有 CDP 的 App 测试不得出现空浮窗。

## 1. 目标与成功标准

1. 在原会话中显示规划阶段、业务步骤图、当前步骤、逐步结果与实际耗时，保留原生计划审核和执行方式。
2. 图与状态来自插件已校验计划和执行记录；动作、断言、准备、清理各按实际结果展示。
3. 实时预览复用 Browscreen 的 PNG 输出和 DSH 原生浮窗；取得当前运行的 CDP 且收到有效首帧之后才自动打开。
4. 未配置预览、CDP 缺失或不可达、纯 API 任务和无 CDP 的 App 任务均不创建画面浮窗。
5. 预览失败不阻断测试；关闭浮窗不停止业务；停止测试沿用现有结算、清理和隔离规则。
6. 完成类型检查、构建、相关单元与集成测试，以及真实 DSH 页面中的 API 无浮窗和浏览器有画面验收。

首版交付步骤图与墙钟耗时；PlantUML 渲染、剩余时间预测和鼠标轨迹不纳入本轮。

## 2. 界面组织

视觉基调：沿用宿主主题，以清晰的节点连线、文字层级和单一进度强调色展示状态。

内容顺序：当前阶段与整体时间、当前实例、业务步骤图、检查点及准备/清理详情；浏览器画面放在独立原生浮窗中。

交互：节点状态平滑切换，当前节点使用克制的运行提示；画面只在首帧就绪后出现。尊重减少动态效果设置，界面没有数据时不挂载空区域。

进度入口放在会话输入区上方和标题旁的官方扩展位置；详细步骤可在插件侧栏页展开。原生审核接管输入区时，标题旁入口仍能打开步骤图。批量用例只展开当前实例，允许查看其他实例结果。

## 3. 服务端改动

### 3.1 展示快照

增加职责独立的展示投影模块，从 NativeTest 的已校验草案、冻结计划、实例、当前步骤与结果生成快照。仅输出展示需要的字段，先应用既有脱敏，不输出完整工具参数或全部观察。

快照至少包含 session_id、run_id、服务端时间、运行阶段、计划名称、当前实例及业务步骤、开始/结束时间、状态、检查点结果、准备/清理状态和报告链接。终态停止计时，未执行节点保持待执行；计时标明包含等待。

按会话查询活动或最近运行，避免复用全局最近报告摘要造成串会话。复用宿主 webServer 和 connection.authorizeIndex，增加只读路由，不写入宿主会话事件。

### 3.2 预览条件

预览采用独立可选配置，复用 workspace 和 outputRoot。配置指明 CDP 交付工作目录、Browscreen 服务地址及可选本机项目路径；不配置时进度功能仍正常。

当前浏览器资源属于该运行 → 读取带运行身份的 CDP 交付信息 → 确认页面端点 → 启动或连接 Browscreen → 获取有帧编号、采集时间的有效 PNG → 标为 ready。

缺少任何前置条件都不返回可打开的预览。新运行和新页面清除上一目标的就绪状态；旧请求不能发布为新目标帧。认证图片路由保留 no-store 和帧元数据。

旁路采集进程只在需要时启动，只释放自己启动的进程；CDP、截图或采集错误不改变业务结果。业务结束时释放预览资源，不延迟现有测试结算。

## 4. CDP 交付选择与 V0 验证

优先验证比独立管理浏览器更小的接法：利用当前 Playwright MCP 公开的 --init-page 页面初始化扩展，在 Node 侧通过公开 CDP 命令取得当前页面 target 和 Chromium 实际调试端口，将页面 WebSocket 地址交付到预览目录。

验证 Browser.getBrowserCommandLine、Target.getTargetInfo、HTTP target 列表及初始化脚本的实际返回和执行时机。若此路径通过，则保留 MCP 原有浏览器启动、isolated 上下文和清理语义，不改变浏览器所有权。若不支持，仅禁用预览并报告边界，不为获得画面而放开任意工具或扫描系统浏览器。

初始化扩展应只发布自己所属页面的 CDP，不执行用户业务、不读取私有 Playwright 字段。没有 CDP 的浏览器/设备适配器可以继续运行测试而不发布预览。

首版仅验收单活动页面；多标签选择与自动跟随若未实际验证，明确列为边界，不能用相同 URL 推断页面身份。

## 5. 前端与构建

在同一插件包增加 ./client 导出和 dsh.client 声明。使用与锁定宿主一致的模块注册格式构建浏览器 bundle，React 和 Cordis 采用宿主提供的模块，客户端不引入 node:*。

通过官方 conversation.input.dock 和 sidebar.right.pane.tab 插槽注册组件，通过 sidebarRightTabs 与 sidebarRight.float 创建浮窗。轮询约 1 秒取得按会话隔离的快照，本地更新计时文字；切换会话、卸载或关闭可见区域时取消在途读取。

自动打开策略：同一运行首个 ready 帧到达后打开一次；用户关闭后不反复弹出。纯 API 和无 CDP 运行不注册实际浮窗记录。结束后关闭该运行自动打开的画面窗口，保留进度结果与报告入口。

iframe 使用插件同源预览页；页面读取插件认证图片路由，避免 Browscreen 首页中的绝对 /api/screenshot 路径和远程 localhost 混淆。

## 6. 实施与验证顺序

| 阶段 | 交付 | 验证 |
| --- | --- | --- |
| V0 | Client 构建接入及 CDP 交付探针 | 本地 tgz 的前端入口实际加载；MCP 页面准确交付 CDP；Browscreen 得到对应页面 PNG |
| V1 | 展示投影、认证路由、步骤与时间组件 | 草案/批准、当前步骤、失败/跳过/取消、准备/清理、批量实例和会话隔离测试 |
| V2 | 条件预览、旁路生命周期、iframe 和原生浮窗 | 无 CDP/不可达/无首帧不打开；真实首帧才打开；旧帧不串运行；关闭不影响业务 |
| V3 | 安装使用文档与真实网页验收 | API 无浮窗、无头 UI 有变化画面、步骤实时推进、报告结果一致、原有测试回归 |

验收产物保存于忽略的 artifacts/validation/ 下；在开发记录中保留结论和可复查路径。新增单元测试重点覆盖条件门禁、会话隔离和结果投影，真实浏览器测试验证画面来源与宿主扩展装载，不能仅以构建通过代替。

## 7. 实施记录

实施开始时基线：插件 0.6.0，DSH 0.2.1-alpha.1，Playwright MCP 0.0.68。可行性文档和本实施文档属于同一需求，既有测试行为及历史方案保持原样。具体接法和已通过验收在实施完成后补充。

V0 已验证公开初始化扩展接法，采用保持 MCP 浏览器所有权的路径。实际 MCP 加载 ESM 初始化文件时遇到 `.esm.preflight` 限制，交付改为 `cdp-publisher.cjs`；读取调试端口需要在预览配置中增加 `--enable-automation`。这些设置仅用于选择启用预览的专用 MCP。

真实无头 MCP 与 Browscreen 验证得到页面级 CDP，PNG 从第 1 帧增长到第 6 帧，页面变化进入截图，`browser_close` 正常结算。证据位于 `artifacts/validation/progress-preview/v0/`。新增展示和预览门禁验证包含会话隔离、API/无 CDP/无首帧不就绪、旧请求不能发布为新运行帧等场景；最终完整回归和 Web 验收结果另见项目记录。

0.7.0 实施及验收完成，记录见[执行进度与实时预览验收](../project/执行进度与实时预览验收.md)。
