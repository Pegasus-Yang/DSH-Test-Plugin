## 1. 范围与已确认决策

本轮修订涉及 [插件设计](插件设计方案.md)、[数据合同](数据契约与状态规则.md)、[实施方案](详细实施方案.md)、[阶段校验清单](阶段校验清单.md)，并同步首页、导航和上游边界说明。前期纯插件调研及22条证据元数据保持原样；未创建产品代码、未安装依赖、未运行模型/MCP/浏览器或宿主联调。

用户已确认两项功能取舍：

1. 停止业务动作；仅在在途操作全部结算后，执行预先授权的清理。
2. 允许运行中新增必需断言，并据此改变适用实例结果。

因此，收尾超限不执行清理，而是隔离环境并报告不完整；动态必需检查按每个实例实际应用版本聚合，不追溯改判已终结实例。

## 3. 再次审核过程与结果

修订后重新逐份检查设计、合同、实施和验收之间的约束，使用以下反例推演，不依靠文字搜索命中认定功能正确：

| 复审场景 | 合同要求与核对结果 |
| --- | --- |
| 用户取消，工具永不返回 | 有界封存ERROR，清理调用为0，未开始实例CANCELLED；结果结算率不能冒充外部执行完成 |
| 必需工具执行超时，仍未结算 | 活动实例ERROR并隔离，剩余实例BLOCKED；重启保持门禁 |
| 工具已结算，但必要清理需要审批 | 新信号和独立清理Agent的open turn承载审批；拒绝为ERROR，不复用被取消的业务轮次 |
| 准备部分失败，没有完整资源ID | 区分确认不存在与未知；未知无法安全定位时ERROR并隔离，不视为不适用 |
| finish本身也是工具调用 | 控制调用不等待自身；下一步须等待控制调用结束和Agent idle；同批剩余业务调用受终结门禁约束 |
| 同一步有旧页面值、两次采集或迟到返回 | 只接受预绑定输出；争用为ERROR；其他观察仅诊断，冻结后不改判 |
| A已终结、B运行中、C未开始时追加必需断言 | 仅B/C应用；B失败可变FAIL，C满足则PASS，A不变；重建使用各自应用记录 |
| 修订到达时实例正常结束、fail-fast或取消 | 正常最后边界处理已入队修订；fail-fast/取消先关闭入口并拒绝未提交项，不在失败后继续新业务动作 |
| 可选检查失败，后续必需检查成功 | 局部问题只警示、后续继续；记录/身份错误仍ERROR；必要清理成功且无其他问题时PASS |
| 原始计划要求业务输出，工具只返回成功 | ERROR，不能按F07接受；F07必须明确该业务输出非动作完成必需，缺失才为INCONCLUSIVE |

复审中进一步补齐了清理审批的open turn、未知资源处理、finish自等待、修订与fail-fast竞争，以及清理门禁拒绝的ERROR语义。以上补齐均已同步到对应实施步骤和检查点。

本轮静态复审未再发现上述修订范围内阻止进入M0的新合同矛盾。此结论仅表明当前文档可作为验证基线，不代表运行行为已被证明，也不免除M0退出门槛。
