# GitLab 网页用例模板

本文件是用户用例模板；准备脚本会填写占位参数，生成可以直接运行的 ui.md。每个最外层列表项是一条用例，步骤中的预期由固定测试数据定义。只操作本次专用项目。

1. **用例名称：组合筛选后打开正确的 Issue**

   **原始用例**：登录 GitLab，在项目列表通过关闭状态和标签筛选，打开唯一结果，再使用接口独立核对。

   **前置条件**：访问 ${sign_in_url}，使用用户名 ${username} 和密码 ${password} 登录。本次项目已有三条 Issue，其中只有 ${closed_title} 同时为 closed 状态并带 dsh-smoke 标签。

   | 序号 | 操作步骤 | 预期结果 |
   | --- | --- | --- |
   | 1 | 打开项目的工作项列表 ${work_items_url}，在页面选择 Closed，再通过 Label 筛选选择 dsh-smoke；等待列表刷新完成，按列表区域已显示的 Issue 行计数，同一行的标题链接和编号链接只算一个 Issue | 列表中的 Issue 数量等于 1 |
   | 2 | 查看列表中这条 Issue 的标题 | 标题等于 ${closed_title} |
   | 3 | 点击这条 Issue，查看详情主内容区的标题 | 详情标题等于 ${closed_title} |
   | 4 | 独立发送 GET 到 ${closed_api_url}，保存本次响应，后续检查复用这个响应 | HTTP 状态码等于 200 |
   | 5 | 检查同一响应中的 Issue 数组，不重复发送请求 | 响应数组长度等于 1 |
   | 6 | 检查同一响应中第一条 Issue 的 iid | iid 等于 ${closed_iid} |
   | 7 | 检查同一响应中第一条 Issue 的 state | state 等于 closed |
   | 8 | 检查同一响应中第一条 Issue 的 labels 数组 | labels 数组长度等于 1 |
   | 9 | 检查同一响应中第一条 Issue 的第一个标签 | 标签等于 dsh-smoke |

   **收尾**：由插件自动关闭并确认本用例的浏览器释放，不另列关闭浏览器的业务步骤；保留已发现的问题，不编辑 Issue 修正测试结果。

2. **用例名称：预览 Markdown 草稿后取消创建**

   **原始用例**：登录 GitLab，填写草稿并查看 Markdown 预览，取消后确认没有创建 Issue。

   **前置条件**：访问 ${sign_in_url}，使用用户名 ${username} 和密码 ${password} 登录；仅在本次专用项目中操作。

   | 序号 | 操作步骤 | 预期结果 |
   | --- | --- | --- |
   | 1 | 打开新建 Issue 页面 ${new_issue_url}，标题填写 ${draft_title}；切换纯文本 Markdown 编辑模式，正文填写 `**DSH 草稿预览**`，点击 Preview | 已显示的预览正文包含粗体文字 DSH 草稿预览 |
   | 2 | 点击 Cancel；如出现丢弃草稿确认则确认 | 返回列表，页面路径为 ${work_items_path} |
   | 3 | 独立发送 GET 到 ${draft_api_url}，按完整草稿标题搜索 | HTTP 状态码等于 200；响应为长度 0 的空数组 |

   **收尾**：由插件自动关闭并确认本用例的浏览器释放，不另列关闭浏览器的业务步骤；不点击创建或提交，不产生新的 Issue。
